# 鸣牌特征第三阶段：训练完成，选中第150步

修复验证套件元数据兼容后，训练290865完成200步，按预先登记的吃/碰/跳过验证`transfer_nll`选择第150步。训练结果、完整检查点、保存的采样顺序与游标、选模数值及冻结来源核验通过。开发评估290866已自动启动并进入完整东风对局，尚无完整净得点结果，不宣称第三阶段已经提升。

## 训练对象与数据

从第二阶段第200步的LoRA和动作头逐张量精确初始化，372个适配器张量核对通过；未加载旧麻将B的LoRA或头。Qwen3.5-0.8B底座保持冻结，本阶段仍训练约1135万参数，使用新AdamW/OneCycle，LoRA峰值1e-5、头5e-5。实际服务仍由旧B负责普通动作，新分支负责吃、碰、跳过，尚未部署到Windows工具。

TRAIN为前两阶段排除6400条已用请求后的34560条、1582场已有专家比赛：吃1810、碰2871、跳过23015、弃牌6792、立直72。全量token准入34560、拒绝0。没有新增独立比赛，不改变专家标签，也不给固定吃碰奖励。

完整validation仍为1408条、84场，用于整体及分阶段诊断和训练/服务核对；其中1024条、33场reaction原样形成选模子集，吃74、碰114、跳过836。这是同一验证集的子集，不是新的独立测试。TRAIN与validation整场交集为0，封存test未打开。

第0步仅作父模型基线，不重复当成新候选；更新后吃、碰各至少一个精确命中的检查点按真实reaction NLL排序，不要求NLL先超过父模型才允许一次得点评估。按这个事前规则选中150，并非看到对局得分后挑选。第200步已回升，不能简单说继续训练一直变好；所有更新后的吃碰NLL仍差于父模型，净得点效果需独立验证。

实际`selection.json`记录`metric=transfer_nll`、`step=150`、`value=0.33088798854760443`。reaction子集独立评估值与完整validation中reaction分组的NLL误差小于1e-12；两套指标含义保持独立。若按整体NLL会选更新后的第100步，不能混称本阶段仍按整体一致率或整体损失选模。

## 实际训练覆盖

整轮200步、每步有效batch16，实际更新3200条请求；第150步选中权重的新增覆盖为2400条、1206场，其中吃122、碰209、跳过1585、弃牌479、立直5。后50步的800条不计入选中权重的覆盖，不能把3200条全部算作第150步学过的数据。

三个特征阶段选中权重的请求ID两两交集为0，合计8800条。若计算三个阶段实际执行过的全部更新，则共9600条；原40960池中31360条未用于这三阶段的更新。上述覆盖只针对这三个特征阶段，初始化还包含更早的训练历史，不宣称模型全历史从未见过所有这些局面。

## 评估状态与后续

290866采用新预留10050000–10050031共32个逻辑牌山，四座轮换、三类固定对手，旧B和新候选各384场。候选为冻结的第150步，6条训练/服务概率核对最大误差约3.97e-8、动作一致，另6条普通路由概率不变。通过这些检查后已实际开始对局；尚未读取中途得分来提前判断胜负。

完整对旧B均值为正后，同作业才新增父模型384场，复用候选对局，直接比较第三阶段与第二阶段。条件作业290872等待全部开发和父模型对照成功，只有两项完整审计及身份核对均通过、两个平均净得点差均为正才运行128个新牌山的独立确认。区间跨零仍如实报告，不设固定分数门槛；未提升则保留父权重并依据完整错误、强对手和得点分解调整方案，不盲目续训。
