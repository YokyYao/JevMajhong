# 训练与评测

目标是提高完整东风净得点。当前安装包仍使用 **Jev Play v1**；Value、Value Defense、Kan和Kan EV v1均未取得可采用的净得点改善。当前准备 **Jev Kan Context v3**：从公开局面特征预测杠窗口动作收益差。历史曲线、失败分析和数据扩充记录集中在[实验记录](experiments/results/2026-11-11-tempo-action-learning/README.md)，模型身份见[模型目录](../weights/README.md)。

## 当前训练流程

```bash
python tools/run_experiment.py collect-ev --config configs/training/kan-futures.json
python tools/run_experiment.py collect-ev --config configs/training/kan-options.json
python tools/run_experiment.py train-context --config configs/training/kan-context.json
python tools/run_experiment.py evaluate --config configs/evaluation/tempo-development.json
```

模板需要已有的三批完整本地原生采样及Play组件，路径需按实际数据调整。公开恢复程序只恢复已获授权发布的Play组件，不下载私有训练数据或新实验权重。原生采样入口 `collect`、通用训练模板 `tempo-fit.json` 保留用于新数据和不同训练范围。

`collect-ev`严格重放原始动作前缀，还原每个合法杠牌决策。固定四家当前手牌、公开状态和已翻开的宝牌指示牌位置，重排剩余未摸牌，包括未知岭上牌、新宝牌和里宝牌。每个状态预先确定8个随机种子；在同一后续牌山上分别执行Play动作和一个合法替代动作，再以冻结Play及相同对手续打至本局结算。没有强迫杠或吃碰。`wall_scope=unseen`是当前方案，`live_only`仅供复现早期小试。

每个动作对的标签是8组实际收益差的平均值，**仍只算一条样本**。父数据的原始539条杠窗口记录去掉2条重复状态动作对后为537条：400训练、137内部验证。它们来自已有240个整牌山分组，不是537场新比赛，也不是8倍独立训练数据。对手暗手在同一状态的8组未来中保持固定，因此尚未覆盖所有与公开状态一致的暗手可能性。12状态小试用于核对实现，不作为模型实力证据。

标签已全部生成并审计，共8592次本局续打。Context v1、v2复用这些标签；当前v3另外补齐缺少的动作分支，见下节。`kan-fit.json`及`train`保留用于复现EV指针头实验。

## 补齐同状态的可行动作

Context v1、v2在开发中均下降。首次偏离参考动作的路径显示，新选吃碰的对局贡献了主要损失；这包含后续动作影响，不是单动作因果结论。此前杠窗口训练里，吃仅1条训练正例且无负例，模型却对整组合法动作打分，存在覆盖与决策范围不匹配。

`kan-options.json`在原生合法性和既有弃牌保护允许的动作集中，为每个状态补齐所有非参考动作。按原元数据确定同状态代表，不看未来输赢；对照动作与已知替代分支复用，其他动作共用同一8份未来。原537对对应511个不同状态实例，补齐后计划1377对：1011训练／366内部验证，对应379／132个状态实例。仍来自原240个牌山分组，不是新增1377场比赛。计划类别为普通324、吃20、碰300、暗杠327、大明杠287、加杠119；这些是动作对分类数，不是独立机会或正例数。

12状态小试的31对通过完整来源、共同控制分支、结算均值和划分检查；独立还原96份未来并完成344次原生事件重放，观察到95次杠后和牌支付均与独立计分库一致。小试新增152次续打，其他分支复用。完整补全已完成：1377对、511状态，新增6928次本局续打，复用4088个控制和4088个已知分支；没有新增完整比赛。Context v3随后训练9轮、288次更新，在连续4轮未改善后早停，保留第5轮。最新来源按状态等权的验证误差0.047707→0.042697；该数值不能与此前单动作对数据的误差横比。全部10份检查点、输入摘要、原指针头及366条零起点概率检查通过，入选权重已固定用于8牌山完整东风开发。

当前Context v3模板保留v2的152维输入、2464参数结构和相同初始化种子。操作目标权重为普通20%、吃碰各10%、三种杠各20%，单条上限4；再按同状态可行动作数折算并重新归一化、限幅，报告实际配比。验证先在每个状态内平均动作误差，再对状态等权，避免多动作局面重复放大。数据与聚合方式改变后，不将新均方误差与旧数据数值横比。专项验证在每操作／收益方向内按不同状态取最多8例，稀缺仍报告不足，不拿同状态多个选项凑足覆盖。

## 公开上下文组件

`policy/kan_context.py`按固定版本提取152维特征：动作类型、向听变化、门清变化、已有役牌材料、已公开宝牌、手牌对子、立直威胁、巡目、场棒／立直棒及分数差，并包含动作与公开状态的交互。役牌和断幺材料不保证最终有役；未知岭上牌、新宝牌和里宝牌不进入特征。杠后向听描述补牌前状态，不偷看替换摸牌。加杠只移除手中的第四张牌，原碰转换为杠；暗杠保持门清。

以两动作特征差预测已审计的平均本局效用差，使用带正则的加权最小二乘。Context v1线性版使用三个预先固定的正则强度0.01／0.1／1仅需三次CPU线性求解，按最新来源的28条内部验证选择，零系数起点也参与；并非三组完整对局。其余109条内部验证也分别报告，不参与该次正则选择。该版选中0.1，最新均方误差0.036642→0.034184；三来源误差都低于零增益起点。均方误差与旧指针头排序损失含义不同，不横比数值。

底座、LoRA及两套原指针头全部冻结，Context v1训练152个线性系数；Context v2、v3用16个隐藏单元、tanh非线性及标量输出，共训练2464个参数。原生推理仅在合法杠窗口按预测值排序，以极小原策略先验解开收益相同的选择；没有固定杠奖励或要求增加操作次数。普通非杠、纯吃碰仍走Play。启用方式仍为 `candidate_activation=kan_windows` 和普通决策范围。拟合需核对原缓存输入、完整结算与分组，保存特征版本及原模型身份；原生概率预检后才进行完整东风评测。内部预测改善不能证明得点改善。

Context v2及当前v3模板均使用 `fit_model=mlp`，从零收益输出开始，初始概率保持Play；固定学习率0.001、批量32，最多32轮，最新来源均方误差连续4轮未改善就停。v2实际14轮、182次更新，保留第10轮，最新误差0.036642→0.032548。三个来源分别为0.073473→0.072370、0.096090→0.089773、0.036642→0.032548。两者都不从失败的Context v1参数续训。线性版内部误差曾改善，但开发为−545.83点／场，未采用；不能用这些预测误差替代对局净得点。

## 奖励与指针头复现

以下指针头拟合流程对应已停止的EV实验；Context v1使用上面的闭式拟合，v2、v3使用小型非线性网络，两者使用相同本局效用标签。

```text
本局效用 = 本局实际净得点 / 8000
           + 0.1 × 自己本局和牌时的 0.995^剩余全桌摸牌次数
           − 0.1 × 本局是否放铳
```

实际净得点包含本局立直支出与原生结算，一炮多响计入全部实际支付；没有tanh饱和。后续牌局和终局未领立直棒不进入当前动作奖励。吃碰杠次数、番数没有固定加分。这是待检验配方，不能预先保证最优。

冻结底座与LoRA，从Discard v1原动作头初始化，仅训练一个524800参数动作头；纯吃碰头保持Call v1。只在合法候选含暗杠、大明杠或加杠的窗口启用新头，该窗口内的碰、弃牌、跳过等替代动作也一起比较；其他决策继续用Play。评估需同时指定 `updated_scopes=["ordinary"]` 和 `candidate_activation=kan_windows`，程序拒绝将这个专用头用于全决策。

按平均本局效用差直接学习动作排序，并以KL约束偏离Play的程度。目标操作权重为三种杠各30%、碰8%、吃2%；类别内按收益方向及公开立直威胁分层，单条权重最多4，记录实际配比与缺失方向，不复制稀缺案例填数。权重平衡本身也可能带来偏差，需要对局验证。

最多8轮，连续2轮没有合格验证改善就停。按最新来源验证损失选模，第0轮也参与；未超过起点就保留起点。所有来源和风险子集分别报告，避免混合平均掩盖退化。Kan数据中的不利加杠、暗杠验证较少，不能用此前全决策的风险覆盖条件宣称这一子集已通过。

## 数据与审计

- 按原整牌山分组训练／验证；所有座位、原分支和8组未来均留在同组。内部验证已参与调参，真人封存测试集未读取。
- 只读取有完整完成标记的数据；核对原始分片、冻结编码器、实际行为头、规则、请求、合法动作及文件哈希。重复牌山、编码器变化或不完整数据会被拒绝。
- 未来重估保持原输入和历史前缀；逐组核对随机种子、原生点数账本和平均标签。拟合时移除原始逐局记录，只接收缓存输入及一个平均标签。
- 指针头复现流程的续训可用 `initial_heads` 固定父权重和哈希；优化器重建，第0轮逐张量核对。当前Kan EV从Play初始化，不继承失败的Value、Defense或Kan v1参数。
- 启动器冻结源码到本地 `runs/code/`；数据、逐局记录、请求、梯度及新权重均保持私有。GPU预检拒绝被其他计算进程占用的卡。

采样支持 `--resume`，只复用哈希通过的完整分片；须使用相同配置和冻结源码。集群入口见 `cluster/`。当前原始采样也支持普通弃牌、吃、碰、暗杠、大明杠、加杠，以及副露面对立直的定向采样；每种操作同时需要有利和不利案例。

## 完整对局判据

1. 秒级核心检查和动作专项验证先检查规则、隔离、路由与覆盖。每种操作、每个收益方向最多展示8条内部验证，缺少时明确报告。可对完成训练执行 `python -m jevmahjong.evaluation.action_suite --fit-run runs/jev-kan-context-v3 --out runs/jev-kan-context-v3/action-diagnosis.json`。
2. 开发使用8个牌山、四座、三类对手、两臂，共192场完整东风对照。当前10920000起8牌山已经参与多轮选择，只作开发。符合源码、模型、协议、日志和重新计分检查时，通过 `reference_cache_out` 复用已审计的96场参考，只新增96场候选。
3. 固定候选出现正向信号后，才进入32个从未看过的牌山、768场确认；当前预留11030000起32牌山。确认必须保留开发时的模型和启用范围，不能更换候选后沿用旧结论。
4. 主指标为相对Play v1的平均净得点，按整牌山聚合四座和三类对手计算配对区间。独立确认区间下界为正才宣称该模拟协议内改善。同时报告名次、和牌、放铳、速度及各操作的机会与选择数。内部损失、更频繁鸣牌或更高一致率都不能代替实力结果。

开发无改善就分析原因、调整方案；不为同一失败配方继续长训或反复跑大规模确认。完整对局与几秒钟的回归检查是不同任务，见[开发说明](development.md)。
