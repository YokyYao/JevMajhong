## 补齐同状态的可行动作

历史Context v3保留v2的152维输入、2464参数结构和相同初始化种子。操作目标权重为普通20%、吃碰各10%、三种杠各20%，单条上限4；再按同状态可行动作数折算并重新归一化、限幅，报告实际配比。验证先在每个状态内平均动作误差，再对状态等权，避免多动作局面重复放大。数据与聚合方式改变后，不将新均方误差与旧数据数值横比。专项验证在每操作／收益方向内按不同状态取最多8例，稀缺仍报告不足，不拿同状态多个选项凑足覆盖。

## 公开上下文组件

`policy/kan_context.py`按固定版本提取152维特征：动作类型、向听变化、门清变化、已有役牌材料、已公开宝牌、手牌对子、立直威胁、巡目、场棒／立直棒及分数差，并包含动作与公开状态的交互。役牌和断幺材料不保证最终有役；未知岭上牌、新宝牌和里宝牌不进入特征。杠后向听描述补牌前状态，不偷看替换摸牌。加杠只移除手中的第四张牌，原碰转换为杠；暗杠保持门清。

以两动作特征差预测已审计的平均本局效用差，使用带正则的加权最小二乘。Context v1线性版使用三个预先固定的正则强度0.01／0.1／1仅需三次CPU线性求解，按最新来源的28条内部验证选择，零系数起点也参与；并非三组完整对局。其余109条内部验证也分别报告，不参与该次正则选择。该版选中0.1，最新均方误差0.036642→0.034184；三来源误差都低于零增益起点。均方误差与旧指针头排序损失含义不同，不横比数值。

底座、LoRA及两套原指针头全部冻结，Context v1训练152个线性系数；Context v2、v3用16个隐藏单元、tanh非线性及标量输出，共训练2464个参数。原生推理仅在合法杠窗口按预测值排序，以极小原策略先验解开收益相同的选择；没有固定杠奖励或要求增加操作次数。普通非杠、纯吃碰仍走Play。启用方式仍为 `candidate_activation=kan_windows` 和普通决策范围。拟合需核对原缓存输入、完整结算与分组，保存特征版本及原模型身份；原生概率预检后才进行完整东风评测。内部预测改善不能证明得点改善。

历史Context v2、v3均使用 `fit_model=mlp`，从零收益输出开始，初始概率保持Play；固定学习率0.001、批量32，最多32轮，最新来源均方误差连续4轮未改善就停。v2实际14轮、182次更新，保留第10轮，最新误差0.036642→0.032548。三个来源分别为0.073473→0.072370、0.096090→0.089773、0.036642→0.032548。两者都不从失败的Context v1参数续训。线性版内部误差曾改善，但开发为−545.83点／场，未采用；不能用这些预测误差替代对局净得点。

## 历史杠窗口残差策略训练

`kan-context.json`当前使用`fit_model=residual_policy`。同一公开152维输入、16隐藏单元、2464可训练参数，从零输出重新初始化；原语言模型、LoRA和两个指针头保持冻结。只在含杠窗口启用，普通非杠及纯吃碰窗口仍走Play。

历史Context的原策略先验权重仅10⁻⁸，训练后几乎按新收益预测完全重排。新策略保留原概率：`p(a|s) ∝ q_Play(a|s) × exp(gθ(s,a)/0.05)`。0.05为预先固定的本局效用单位强度，原模型越确信某动作，残差就需要提供越大的收益差才会改变选择；没有对吃碰杠单独固定加分。

将每个状态全部可用动作的预注册配对未来平均效用差放到同一向量，参考动作标签为0。蒸馏目标为`softmax(log q_Play + mean_utility/0.05)`，按状态计算交叉熵；缺少任一可用备选就拒绝训练。旧动作／收益方向／风险配比生成的权重在状态内相加、归一化并再次限幅4，实际损失单位为一个完整状态。

按最新来源实际验证状态的平均采样收益遗憾优先选模，即“该状态最高采样效用减去实际所选动作的采样效用”；平手时选择策略KL更低的检查点，其他来源也报告。最多32轮、批量32、学习率0.001，连续4轮上述标准不改善就停，零输出起点参与选模。未提高验证选牌收益就先停止完整开发并修改方案。它仍是参与调参的含噪声内部验证，不代表独立实力。

Residual v1复用同一1377对／511状态和原训练379／验证132状态划分。本轮768场失败确认的原始记录不进入拟合；仅用于结束后的问题分析。56项核心回归通过，包含完整备选检查、零起点、原先验对决策的影响，以及完整动作集收益遗憾。训练完成须再审计全部原参数及直接训练／推理概率。通过后才做8牌山开发，固定正候选才进入预留11040000起32个全新牌山确认。11030000起旧32牌山已经用于v3确认，后续不能再称独立新测试。

Residual v1实际12轮、144次更新，第8轮在收益遗憾平手时凭KL入选，但最新25个验证状态全部保持Play选牌，收益增益为0，未进入192场开发。下一轮固定相同残差方法，补充48个新牌山、定向杠菜单与威胁状态；新状态使用16未来，完整备选生成后与旧8未来来源合并训练。新模型名为`jev-kan-residual-data-v1`，不会复用失败确认作为训练数据。

新48牌山原始采集已完成217条干预记录，核对全部分片、分支网格、结算与模型摘要通过。去重为116个不同状态实例：训练91、验证25；按原动作对去重后有184组，16未来标签已完成5888次本局续打，完整备选补全再新增2688次本局续打。原始记录的吃有6条，实际含吃菜单的不同状态为训练5、验证1；加杠菜单为训练6、验证1，覆盖仍有限。116状态补齐为284对（训练226／验证58），合并旧来源后共1661对、627状态：训练1237对／470状态，验证424对／157状态。残差训练5轮、75次更新，连续4轮无改善后停止，保留第1轮。全部6份检查点、原指针头和157个零输出验证状态的推理核对通过。最新25个验证状态中2个改选，按配对未来重算的平均本局净得点仅+4.75点／状态；这是内部状态标签，不能解释成完整比赛点数提高。该权重的8牌山192场开发已完成，复用已审计96场参考并新增96场候选；所有配对四家终分相同，净得点差0。只有两条路径新增大明杠，真实岭上摸牌、翻宝牌与后续摸牌变化已核对，未改善，因此不进入独立确认。这些共享48个牌山，不能当成116场独立比赛或184份独立局面。

当前Residual Data v2仅把先验强度从0.05降至0.01，训练目标与实际推理同步改变；同数据、网络、初始化、奖励及早停，不从v1参数续训。v1的内部诊断显示部分采样更优动作被先验压制，网络也未充分学到蒸馏目标，不能把失败只归因于先验。这一单变量短训检验能否保留原策略又适度改选；v2实际4轮、60次更新后早停，选择第0轮，最新内部选牌收益未提高；全部5份权重与157个零起点状态的直接推理审计通过，因此跳过完整开发和独立确认。下一步先核查公开特征是否遗漏进张量等可区分备选的信息，再决定表示改进；不继续仅搜索先验强度。

同一状态8未来的均值仍有随机误差，吃的独立状态仍少；不能预先保证本轮解决这些限制。新权重与原始记录保持私有，Windows仍使用Play v1。

## 历史杠窗口进张特征候选

Residual Data v1开发差0，减弱先验的v2在内部验证也未改善，均停止。结构诊断发现，在有多种弃牌并提供公开进张量的状态中，旧152维特征无法区分进张不同的部分备选：训练86／126状态、验证25／37状态；对应500／290对同特征不同进张的选项。原策略概率仍可能不同，因此不把这个缺口当成全部失败的唯一原因。

Progress v1使用明确版本`public-kan-context-v2`。保留原152维特征作为前缀，再加6项：进张张数上下界、有效牌种数上下界、保留在暗手中的已公开宝牌和赤牌，共158维；16隐藏单元、2560可训练参数。旧版检查点继续按v1的152维解释，拒绝混用名字或张量形状。

弃牌动作优先采用原公开请求里已有的精确`ukeire`；其他动作在最佳向听的可弃选择中，计算公开可见库存下的进张界限。碰和明杠的被叫牌与原牌河去重；历史请求未保存吃进的具体那张时，用牌河约束保留上下界，不猜成精确库存。各牌种界限可能不能同时取到；这些是公开可用数量界限，不是摸牌概率。杠仍在未知岭上摸牌前计算，不读取其他暗手、未揭示宝牌或未来。进张与保留牌值是各自的选择摘要，不保证来自同一次后续弃牌。

本轮恢复Residual Data v1的0.05先验，固定相同四来源、整牌山划分、奖励、隐藏层大小、种子及早停，只改变可观察表示及相应输入层；不从任何失败权重续训。61项核心检查通过，包括同旧特征不同进张、赤牌保留、叫牌去重／吃牌歧义、零起点及实际推理一致。短训完成后审计全部权重与分组；内部选牌采样收益无改善就跳过完整开发，合格候选才做8牌山192场；固定正向候选才做全新32牌山确认。没有证明净得点提升前，Windows继续使用Play v1，新权重与原始记录保持私有。

## 奖励与指针头复现

以下指针头拟合流程对应已停止的EV实验；Context v1使用上面的闭式拟合，v2、v3使用小型非线性网络，两者使用相同本局效用标签。

```text
本局效用 = 本局实际净得点 / 8000
           + 0.1 × 自己本局和牌时的 0.995^剩余全桌摸牌次数
           − 0.1 × 本局是否放铳
```

实际净得点包含本局立直支出与原生结算，一炮多响计入全部实际支付；没有tanh饱和。后续牌局和终局未领立直棒不进入当前动作奖励。吃碰杠次数、番数没有固定加分。这是待检验配方，不能预先保证最优。

冻结底座与LoRA，从Discard v1原动作头初始化，仅训练一个524800参数动作头；纯吃碰头保持Call v1。只在合法候选含暗杠、大明杠或加杠的窗口启用新头，该窗口内的碰、弃牌、跳过等替代动作也一起比较；其他决策继续用Play。评估需同时指定 `updated_scopes=["ordinary"]` 和 `candidate_activation=kan_windows`，程序拒绝将这个专用头用于全决策。

按平均本局效用差直接学习动作排序，并以KL约束偏离Play的程度。目标操作权重为三种杠各30%、碰8%、吃2%；类别内按收益方向及公开立直威胁分层，单条权重最多4，记录实际配比与缺失方向，不复制稀缺案例填数。权重平衡本身也可能带来偏差，需要对局验证。

最多8轮，连续2轮没有合格验证改善就停。按最新来源验证损失选模，第0轮也参与；未超过起点就保留起点。所有来源和风险子集分别报告，避免混合平均掩盖退化。Kan数据中的不利加杠、暗杠验证较少，不能用此前全决策的风险覆盖条件宣称这一子集已通过。

## 数据与审计

- 按原整牌山分组训练／验证；所有座位、原分支和8组未来均留在同组。内部验证已参与调参，真人封存测试集未读取。
- 只读取有完整完成标记的数据；核对原始分片、冻结编码器、实际行为头、规则、请求、合法动作及文件哈希。重复牌山、编码器变化或不完整数据会被拒绝。
- 未来重估保持原输入和历史前缀；逐组核对随机种子、原生点数账本和平均标签。拟合时移除原始逐局记录，只接收缓存输入及一个平均标签。
- 指针头复现流程的续训可用 `initial_heads` 固定父权重和哈希；优化器重建，第0轮逐张量核对。当前Kan EV从Play初始化，不继承失败的Value、Defense或Kan v1参数。
- 启动器冻结源码到本地 `runs/code/`；数据、逐局记录、请求、梯度及新权重均保持私有。GPU预检拒绝被其他计算进程占用的卡。

采样支持 `--resume`，只复用哈希通过的完整分片；须使用相同配置和冻结源码。集群入口见 `cluster/`。当前原始采样也支持普通弃牌、吃、碰、暗杠、大明杠、加杠，以及副露面对立直的定向采样；每种操作同时需要有利和不利案例。

## 完整对局判据

1. 秒级核心检查和动作专项验证先检查规则、隔离、路由与覆盖。每种操作、每个收益方向最多展示8条内部验证，缺少时明确报告。可对完成训练执行 `python -m jevmahjong.evaluation.action_suite --fit-run runs/jev-kan-residual-v1 --out runs/jev-kan-residual-v1/action-diagnosis.json`。
2. 开发使用8个牌山、四座、三类对手、两臂，共192场完整东风对照。当前10920000起8牌山已经参与多轮选择，只作开发。符合源码、模型、协议、日志和重新计分检查时，通过 `reference_cache_out` 复用已审计的96场参考，只新增96场候选。
3. 固定候选出现正向信号后，才进入32个从未看过的牌山、768场确认；当前预留11040000起32牌山；11030000起旧32牌山已用于v3确认。确认必须保留开发时的模型和启用范围，不能更换候选后沿用旧结论。
4. 主指标为相对Play v1的平均净得点，按整牌山聚合四座和三类对手计算配对区间。独立确认区间下界为正才宣称该模拟协议内改善。同时报告名次、和牌、放铳、速度及各操作的机会与选择数。内部损失、更频繁鸣牌或更高一致率都不能代替实力结果。

开发无改善就分析原因、调整方案；不为同一失败配方继续长训或反复跑大规模确认。完整对局与几秒钟的回归检查是不同任务，见[开发说明](development.md)。
