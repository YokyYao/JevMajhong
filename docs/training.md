# 训练与轻量评测

当前目标是提高完整东风净得点。Jev Value v1的768场独立确认相对现用Play v1为−1115.36点／场，区间跨零，未采用。下一轮Value Defense v1补充候选策略实际到达的副露防守局面，保持以下净得点主奖励不变；当前仍处于新数据采集阶段。

```text
奖励 = 本局实际净得点 / 8000
       + 0.1 × 自己本局和牌时的 0.995^剩余全桌摸牌次数
       − 0.1 × 本局是否放铳
```

放铳按局计，一炮多响的实际全部支付仍进入净得点。点数项包含本局立直支出与结算，保留大额支付的幅度，不使用旧风险配方的tanh饱和。后续牌局和终局未领立直棒的归属不计入当前动作奖励。番数、吃碰次数和杠次数不直接获得固定奖励。权重是待检验配方，不是最优参数结论。可从原采样的实际日志重算标签，无需重跑对局；原始快和标签与公开输入保留原样。旧风险配方仍可用 `risk_adjusted_fast_win_v1` 重现。

## 数据覆盖与配比

新采样入口分别处理普通弃牌、吃、碰、暗杠、大明杠和加杠。每种操作都需要有利和不利对照；缺少某种正例时，报告覆盖不足，不以重复复制一条稀缺样本充当充足数据。原生引擎提供合法动作，同状态只改变一个动作并继续对局，用实际本局结果产生标签。

训练模板将目标损失权重设为普通决策40%，五种操作各12%；各类别再分配到实际存在的收益方向。单样本权重最多为4，报告实际支持数、缺失方向及有效权重。目标比例与实际达到的比例分别记录。底座和 LoRA 冻结，训练两个动作头。

当前模板使用直接动作排序：按实际本局效用收益差，学习两个动作的当前分数高低；KL 仍约束它偏离原策略的程度。`reference_margin_weight=0` 表示直接排序，`1` 可复现此前相对原模型边际变化的对照。两种目标的损失值不能横向比较，需看同一组动作诊断与完整对局。

Value Defense v1最多训练8轮，连续2轮未取得合格验证改善即停，起点参与选模；新来源整体验证改善还需满足副露立直子集损失不高于起点。Value v1此前最多12轮，实际在第5轮停止，选中第3轮。不同奖励目标下的损失和专项标签不同，不横向比较绝对值。详见[动作学习诊断与对局结果](experiments/results/2026-11-11-tempo-action-learning/README.md)。

```bash
python tools/run_experiment.py collect --config configs/training/tempo-native.json
python tools/run_experiment.py train --config configs/training/tempo-fit.json
```

模板引用本地私有Value v1入选权重；需已有该权重及原两批完整数据才能直接执行，公开的模型恢复程序只恢复已获授权发布的Play v1组件。历史配方可从对应提交追溯。

整牌山划分训练／验证，所有座位和反事实分支同组。人类封存测试集不参与调参；当前原生采样配置不读取真人牌谱。已有数据可复用，但需完整完成标记和分片校验。

加数据时，配置的 `data` 也可填多个采样目录，例如 `["runs/tempo-native-original", "runs/tempo-native"]`。程序核对每个来源的完整牌山范围、原生结算记录、分片哈希、规则与奖励定义，以及两套冻结编码器的身份；重复牌山、不同底座／LoRA或不完整采样会被拒绝。每个来源保留原先的整牌山划分，不把旧验证样本移入训练。所有缓存动作概率还需与各来源真实采样策略的动作头逐条对应；新增来源可通过 `behavior_heads` 指定冻结候选，记录文件哈希。不能拿候选策略的缓存概率与旧头直接比较。强对手仍使用原头，玩家临时切换后必须恢复。

新增96个牌山已完成1353条分支；合并原975条后共2328条，其中1741条训练、587条内部验证，对应144个训练牌山和48个验证牌山。原来源占259条验证、新来源328条。内部验证已参与过调参，完整实力确认仍需另外的独立牌山。

数据目录按旧到新排列。当前 `selection_validation=latest_source` 只按最后一个来源的验证损失选模和早停，同时记录所有来源损失，监控旧能力。旧 `all_sources` 模式保留用于历史重现。Safe Data v1的旧验证改善曾掩盖新验证退步；其所有新增轮次在新验证集上都未超过起点，不能把混合平均下降当作新数据泛化改善。

扩充数据续训可通过 `initial_heads` 指定上次结果中的 `selected.checkpoint` 与 `selected.sha256`。先逐条核对缓存与原参考头，再加载入选动作头继续优化；两套底座和LoRA保持相同。起点文件在训练前后都核对哈希。当前Value Defense v1计划从Value v1第3轮继续，历史Safe Data v1从Safe v1第6轮继续；优化器重新建立，属于模型参数续训，不是优化器状态的精确恢复。

训练把续训前的参数作为第0轮保存并纳入选模。新轮次未优于起点时保留第0轮；选中第0轮表示沿用起点参数，可以复用其现有对局记录。第0轮已使用实际两套动作头逐张量验证与起点相同。

可用已完成训练记录重做训练／验证动作诊断，无需加载底座或运行新对局：

```bash
python -m jevmahjong.evaluation.action_suite --fit-run runs/jev-value-v1 --out runs/jev-value-v1/action-diagnosis.json
```

诊断同时报告原策略与候选的操作概率、是否实际选中，以及奖励方向上的动作边际变化。概率提高不算动作选对，训练样本拟合也不算验证或实力提升。

## 每轮检查

1. 先检查数据覆盖和五种操作的专项验证。每种操作按收益正／负各取最多8条内部验证案例，报告排序判断及缺失项；这是采样续打结果的验证标签，不能当作绝对最优动作证明。
2. 普通开发使用8个牌山、四座、三类对手、两臂，共 **192场完整东风对照**。同一开发协议可复用已完整审计的参考臂：配置 `reference_cache_out` 指向前一次完整结果，只新增候选的96场对局。程序核对牌山、阶段、规则、参考模型、影响出牌的源码及原始日志哈希，并重算得分和速度；条件不符即拒绝复用。开发数据不用于独立确认。
3. 净得点有正向信号时，固定候选进入32个新牌山的 **768场确认**。下一轮开发预留10920000起8个牌山、独立确认10930000起32个牌山；已经分析过的Value和Safe确认集不再作为新候选的独立测试。当前模板明确以净得点为主目标，同时报告和牌、速度、按局放铳、吃碰和三种杠的机会／选择数；速度指标不单独否决得点改善。此前登记的纯快和联合目标对照仍按其原协议解释。不为每次小更新跑几千场，也不以动作一致率代替实力。

```bash
python tools/run_experiment.py evaluate --config configs/evaluation/tempo-development.json
python tools/run_experiment.py evaluate --config configs/evaluation/tempo-confirmation.json
```

小规模结果用于快速筛选，区间通常更宽；配比保证覆盖，不能消除对局随机性。正向但不确定时保留候选，必要时追加独立牌山。某种操作未达到覆盖量时明确标记，不能判成通过。

历史固定协议仍按原登记解释。旧的大规模待运行评测已撤销，正在运行的数据采集及已完成记录保留；后续使用精简方案，不修改祖先实验的冻结代码和数据。


## 副露防守数据阶段

当前采样使用48个新牌山，36个训练、12个内部验证；除六类原干预外，再按可见状态选取 `ordinary_open_threat`、`chi_threat`、`pon_threat`。候选Value v1作为采样及续打策略，不代表它已取代部署模型。一次GPU联调通过后才开始完整采样。

`context_mix`在操作／收益方向内分层：副露且面对立直40%、其他面对立直20%、无立直40%；单条权重上限4，报告实际达到的占比。方向、上下文稀缺时不复制填补。正式拟合要求最新来源副露立直子集至少32条训练、8条内部验证非零收益对比；不足则零更新退出，继续补数据。这是最低覆盖要求，不是实力证明。

`validation_guard_contexts`要求入选轮在新来源的指定风险子集损失不高于第0轮；仍需新来源整体损失下降。每轮报告新旧来源以及各公开风险子集，不用内部损失或更多鸣牌直接宣称比赛得点改善。完整方案与失败结果在[实验记录](experiments/results/2026-11-11-tempo-action-learning/README.md)。
