# 训练与轻量评测

当前目标是提高完整东风的实际表现。当前候选 Jev Tempo Rank v1 使用本局实际和牌及速度奖励；仅在自己和牌时给予 `0.995^剩余全桌摸牌次数`，对手先和或流局为零。番数、吃碰次数和杠次数不直接获得固定奖励。

## 数据覆盖与配比

新采样入口分别处理普通弃牌、吃、碰、暗杠、大明杠和加杠。每种操作都需要有利和不利对照；缺少某种正例时，报告覆盖不足，不以重复复制一条稀缺样本充当充足数据。原生引擎提供合法动作，同状态只改变一个动作并继续对局，用实际本局结果产生标签。

训练模板将目标损失权重设为普通决策40%，五种操作各12%；各类别再分配到实际存在的收益方向。单样本权重最多为4，报告实际支持数、缺失方向及有效权重。目标比例与实际达到的比例分别记录。底座和 LoRA 冻结，训练两个动作头。

当前模板使用直接动作排序：按实际快和收益差，学习两个动作的当前分数高低；KL 仍约束它偏离原策略的程度。`reference_margin_weight=0` 表示直接排序，`1` 可复现此前相对原模型边际变化的对照。两种目标的损失值不能横向比较，需看同一组动作诊断与完整对局。

最多训练12轮，连续2轮验证损失不改善即停，保留验证最优轮次。实际旧数据短程对照在第5轮停止，选中第3轮；延长运行选中权重与3轮短训逐张量相同。详见[动作学习诊断](experiments/results/2026-11-11-tempo-action-learning/README.md)。

```bash
python tools/run_experiment.py collect --config configs/training/tempo-native.json
python tools/run_experiment.py train --config configs/training/tempo-fit.json
```

整牌山划分训练／验证，所有座位和反事实分支同组。人类封存测试集不参与调参；当前原生采样配置不读取真人牌谱。已有数据可复用，但需完整完成标记和分片校验。

可用已完成训练记录重做训练／验证动作诊断，无需加载底座或运行新对局：

```bash
python -m jevmahjong.evaluation.action_suite --fit-run runs/jev-tempo-rank-v1 --out runs/jev-tempo-rank-v1/action-diagnosis.json
```

诊断同时报告原策略与候选的操作概率、是否实际选中，以及奖励方向上的动作边际变化。概率提高不算动作选对，训练样本拟合也不算验证或实力提升。

## 每轮检查

1. 先检查数据覆盖和五种操作的专项验证。每种操作按收益正／负各取最多8条内部验证案例，报告排序判断及缺失项；这是采样续打结果的验证标签，不能当作绝对最优动作证明。
2. 普通开发使用8个新牌山、四座、三类对手、两臂，共 **192场完整东风**。看净得点、和牌、速度、放铳，以及三种杠的机会和选择数。
3. 只有完整结果存在正向信号时，固定候选进入32个新牌山的 **768场确认**。不为每次小更新跑几千场，也不以动作一致率代替实力。

```bash
python tools/run_experiment.py evaluate --config configs/evaluation/tempo-development.json
python tools/run_experiment.py evaluate --config configs/evaluation/tempo-confirmation.json
```

小规模结果用于快速筛选，区间通常更宽；配比保证覆盖，不能消除对局随机性。正向但不确定时保留候选，必要时追加独立牌山。某种操作未达到覆盖量时明确标记，不能判成通过。

历史固定协议仍按原登记解释。旧的大规模待运行评测已挂起，正在运行的数据采集及已完成记录保留；后续使用精简方案，不修改祖先实验的冻结代码和数据。
