# Play 实战吃碰问题：冻结权重复查与输入修复

已同步 GitHub 的[Windows 实测证据](../2026-11-12-windows-live-test/README.md)。本次优先修复当前 Jev Play v1 的实际使用问题；没有替换已发布权重或生成新安装包。

## 复查得到什么

31次吃碰推荐事件去重后，有27份独立截图预测记录、33个吃碰候选，均已进入合法菜单且未被工具过滤，最后都选跳过。不同记录仍可能属于相近局面，不能视为27个独立专家测试样本。

固定已部署 Call v1 权重做了66次推理：27份实战输入重建、其中3份补入人工核准的部分场况，以及12份原生训练场景各3种输入视图。结果如下：

| 对照 | 场景数 | 首选吃碰 | 含义 |
| --- | ---: | ---: | --- |
| 实战重建，未确认场况保持未知 | 27 | 0 | 重现了全部跳过的现象 |
| 上述场景补入已核准分数、庄家等部分信息 | 3 | 0 | 补这些信息没有改变选择 |
| 原生训练对照 | 12 | 6 | 特意选择6个原模型吃碰、6个跳过，不能估计自然鸣牌率 |
| 同一训练对照，截图时序未知／场况已知 | 12 | 6 | 全部动作保持一致 |
| 同一训练对照，截图时序及部分场况未知 | 12 | 6 | 全部动作保持一致 |

原生概率与缓存最大差为2.64×10⁻⁷，校验通过。12份对照中的吃碰为5个碰、1个吃；其中门清开碰4个，已经副露后的碰、吃各1个，**不能用它证明门清吃牌加速已经学好**。

历史记录没有保存完整模型请求，分数、庄家、手动立直标记等无法全部还原，因此这里是输入重建，不是精确历史回放。3张人工核准截图也不构成最优动作标签。不能把全部跳过直接反转为吃碰。

## 发现的代码问题与修复

- 鸣牌路径此前会覆盖已确认字段清单，导致手动确认的对手立直在进入模型前被清空。现在保留逐字段确认，未知分数、庄家等继续保持未知。
- 自动推荐缓存此前漏掉牌河、他家副露、分数、宝牌等变化。现在这些公开决策输入变化会使旧推荐失效。
- 本地记录新增源请求、模型路由和实际送入编码器的请求；同一截图在场况变化后可保留多次不同输入的预测，便于精确复查。输出仍是模型预测，不自动变成专家标签。
- 自家立直后禁止吃、碰、大明杠；和牌与跳过仍可用，摸切锁定保留。

这些修复不能代替模型强度改善，也**没有实现可靠的对手立直自动视觉识别**。目前保留的是已确认的立直事实；不能将其他未标记座位解释为已确认未立直。已发布 EXE 尚未包含本轮源码修改。

## 训练覆盖里的具体缺口

核对现有240整牌山来源的全部分片后，门清、断幺材料、吃后向听降低这一细分类中，训练端仅有65个不同动作选项：无立直威胁34个、有威胁31个，参考模型全部不选吃。其中24个选项的16未来采样效用偏向吃，另有38个偏向跳过、3个持平。该细分类存在漏吃值得检查，也有大量应当跳过的情况；不能只补吃的正例。它们是采样效用符号，仍有噪声，不是24个专家确定错误。

这说明只按“吃／碰”统计总量会掩盖路线覆盖问题。下一步按门清断幺加速、役牌开碰、对手立直后的门清路线和普通反例分层补数据，见[Play 鸣牌路线修复方案](../../plans/play-call-routes-20261112.md)。后续短训结果见下文，尚无修复后权重的完整对局改善结论。

## 动作头短训结果与用户明确的“先和牌”目标

得点优先的Call Routes v1在6轮60次更新后早停，选第2轮。50个验证局面的采样本局净点差平均+172.38，但9个门清断幺吃牌加速局面为−92.36，4个采样正收益局面未恢复；整体改善主要来自役牌碰。完整开发被跳过，0场，不采用。这些单位是局面及16未来的平均结算差，不能解释为每场比赛提升。

用户随后明确本局先和更重要。之前把少量指定吃牌局面的改选作为整体开发硬门槛，过于具体；它现在保留为问题诊断，整体效果须由完整对局的和牌率与速度验证。对应[和牌率优先方案](../../plans/play-own-win-20261112.md)不再要求候选净得点为正才有资格测试，也不会把旧失败结果重写成成功。

Call Win v1使用同一批已核对原始事件重算奖励：自己实际和牌+1，速度奖励只在自己和牌时产生，放铳额外−1，净点不参与奖励。同速度的1000点与8000点和牌基础奖励相同；对手先和、自己未和没有正奖励。它同样在6轮60次更新后早停，选第2轮。内部先和概率估计+2.25个百分点，放铳概率+0.875个百分点，采样净点+146.50点／局面；它们不是完整比赛效果，吃牌子组仍未恢复，不能宣称问题已全部解决。

8032条两臂记录的赢家、等待时间和新奖励已按原始事件另行重算。完整对局开发使用尚未消费的8个新牌山、四座位、三类对手、两策略，192场；和牌率为主指标，速度、放铳、净点和名次同时报告。本轮更改来自用户目标澄清，在完整比赛结果产生前登记。

## 192场开发结果与下一步

192场（候选、参考各96场，8个完整配对牌山）及独立赢家、支付、名次复算已完成。主指标是各场单局和牌率等权再按牌山配对：参考20.858%、候选22.669%，差+1.811个百分点，95%区间[−1.768,+5.389]个百分点。放铳配对差+1.750个百分点，超过预先登记的+1个百分点上限；净得点差+133.33点／场，区间[−901.10,+1167.76]。一位率29.17%→37.50%，前二率均67.71%，均属这批开发牌山的描述结果。汇总所有单局的和牌率21.580%→23.715%与等权主指标口径不同。

因此它显示了正向和牌信号，但未通过风险约束，且区间尚不能确认稳定改善。没有因为净点提升不够而拒绝它，没有部署或进入独立确认。[完整聚合摘要](win-development-summary.json)保留各项口径。

下一轮Call Win v2只将放铳惩罚由1增加到2，自己实际和牌+1及速度奖励保持不变；同数据、初始模型、种子、学习率与早停规则，做可解释的短训对照。普通出牌与杠策略仍冻结。拟合、原始目标检查和有条件开发任务已经依次提交，开发使用另外8个牌山11420000—11420007。没有增加同数据训练轮数，也没有将失败开发重作独立测试。若没保住先和收益，就继续改数据覆盖，不将更高鸣牌次数当作成功。


训练端进一步诊断发现：放铳惩罚加倍后，5个目标首选改变，但模型在156个训练状态的首选没有变化。门清断幺吃牌加速仍有目标倾向吃而模型跳过的缺口，见[聚合诊断](win-training-diagnostic-summary.json)。下一步已登记公开路线损失加权对照，正反例均保留、验证不加权；完整评估仍须证明改善，详见[更新方案](../../plans/play-own-win-20261112.md)。
