# Stage4 public tile inventory and constrained prior preparation

2026-11-21, Asia/Dubai. These are development data-generation checks without model loading, optimizer updates or teacher labels. They do not change current calls/attack-bound sources or establish stage4 admission.

`tools/curriculum_public_inventory.py` derives physical tile inventory from the observing player's own hand, public rivers/melds and revealed dora indicators. It rejects observations exposing another concealed hand. A called tile appearing in both its source river and meld is counted once; other duplicate physical identities fail. Each opponent's concealed count is13 minus3 per meld, including a four-tile kan. The remainder is divided conceptually into concealed opponent slots and unknown nonhand slots; no wall/dead-wall layout or hidden result is read.

The inventory retains an explicit tenpai requirement for every declared riichi opponent. An unconstrained diagnostic explains why this matters: in9 riichi-constraint exposures in the calling-profile windows, only2 of4,608 independently sampled candidate hands were tenpai. These inspected cases do not estimate a general population rate, but plainly show that uniform random hands cannot simply be admitted as valid riichi worlds.

`tools/curriculum_public_worlds.py` now offers bounded rejection sampling. Shuffle all unknown physical tiles, allocate all three opponent hands and remaining nonhand slots, and reject the entire allocation unless every declared riichi hand is tenpai. It does not separately resample players and silently change the joint prior. If the budget expires, it raises an explicit exhaustion with counts and returns no partial case as complete. No invalid-hand fallback or actual opponent concealed hand is used. The generic cap is128 requested allocations and2,000,000 attempts; this native precheck requested8 per window with200,000 attempts allowed per window.

This is a uniform physical-allocation prior conditioned on the listed inventory/tenpai constraints. It is **not** a calibrated posterior given the complete public action history. It does not construct a native continuation environment, infer missed-win/furiten history or distribute dead-wall/ura positions. These remaining steps must be validated before terminal teacher labels can be admitted.
