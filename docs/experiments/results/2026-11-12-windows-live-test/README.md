## 用户新增策略要求：对手立直必须重新评估

**发现任意对手新立直，必须触发一次整体路线重评估，不能继续机械等待原来的进张或听牌。** 重评估包含下列实际选择：

1. 自家尚未立直时，重新比较保留门清、合法有役的吃碰加速、维持听牌以及退听防守。特别复查已经有役牌、可走断幺九、可通过副露降低向听或立即听牌的正例。
2. 吃碰后必须仍有合法弃牌和可完成的役种；比较随后的危险弃牌、放铳代价、和牌速度、打点和当前顺位。不能将要求实现为“对手立直就一律吃碰”，也不以吃碰次数增加作为训练奖励或验收目标。
3. 原路线等待较窄或明显偏慢时，要主动比较转型和加速方案；危险过高时允许选择现物、退听或弃和，不能为了加速而强制打危险牌。
4. 自家已经立直时遵守锁手规则，不能改为吃碰或交换手牌；摸到赤牌也不能随意换下原手牌。界面要明确区分强制摸切和模型自由选择。
5. 界面持续说明当前路线及变化原因，本次决策单独显示动作。不能用“尚未副露”直接推出“模型决定保持门清”。

### 先补输入与触发，再做策略验证

目前截图端尚不能保证完整读取对手立直状态、分数、庄家及场况；未知信息不能伪装为已确认。需要先核对对手立直棒／宣言弃牌等可见信号、正确座位、场风、牌河与副露，并确保状态变化使旧推荐失效，重新产生输入。否则只修改提示词或训练模型不能保证这条规则在真人局生效。

本节是**新增修复／训练验收要求，尚未作为新的训练策略或可靠视觉触发部署**。本次推送的工具代码仅包含已测的本机杠与文案修复；没有改写冻结模型指令或已注册实验奖励，也没有启动训练。

## 当前优先级与验收

首要问题仍是吃碰：逐条人工核准31次推荐，筛出“有役且明显加速却跳过”的待审场景，并增加对手立直后的正例、应当跳过的反例、混合吃碰菜单及合法性检查。保留整场分组，不能把同一局面的相邻帧分到训练和验证两边。

验收必须同时包含：完整输入审计；确认合法候选不泄漏专家答案；有意义的吃碰正反例；推荐到按钮和多组合选择的实际执行；新副露／补牌后的状态跟踪；对手立直时的路线重评估；独立完整对局的净得点、顺位和放铳。不得以强制鸣牌、单场第一或偏好分升高宣称问题解决。
