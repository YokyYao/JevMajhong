All189 native public requests/menus reproduced, and the teacher's own-hand
history and chi/pon/three-kan eligibility flags matched the native engine.
Only the correctly redacted actual public prefix reached each fresh actor;
source walls and construction motifs were not teacher inputs. Every network
intention mapped uniquely to a legal physical candidate and was submitted to
the native engine. Simultaneous priority may override a call intention.
Scripted prefix actions never become labels. The task completed in11 seconds
with an actual successful scheduler exit after moving to a free identical GPU.

This adds positive ankan/kakan labels but **does not fill the positive
daiminkan gap**. Every non-win daiminkan opportunity still receives PASS.
The source construction has a specific limitation: all daiminkan cases are
closed-hand responses by seat1 to dealer0's first discard, immediately before
the observer's normal draw. It lacks already-open hands, other relative
discarder seats and later threat contexts. That narrow coverage is a reason
to expand future sampling, not proof that every skip is wrong or that all
daiminkan should be skipped. Do not force positive labels or discard valid
negative cases to obtain a desired balance. The validation ankan cohort also
has no negative teacher examples; its16 positives cannot establish balanced
take/skip ability by themselves. These checks cover this189-case pilot,
not all earlier teacher trajectories.

**Student updates on this cohort remain zero.** Teacher agreement alone does
not establish positive action advantage. Conditional-world comparisons, full existing-corpus and
reserved-family overlap, normalization/encoder coverage, loss allocation and
a new training registration are still needed before using these sources in a
fit. The final independent comparison grid remains unopened.

Three source-family/wall/public-history checks passed inside the existing
GPU allocation's companion CPU task. The189 native replays are separate
actual generation evidence. The teacher network and its actual current
choices were exercised by the separate completed labeling task, not by those
three structural checks. Execution has finite
limits, logs and exit receipts; no login computation or background worker is
used. Raw hands, walls, traces and labels remain private.

Run it inside an approved GPU allocation with `--parent-fit-job` set to the
reproducer's actual live3A scheduler job; `--nodelist` is optional. It checks
the source bindings and the three tests before freezing a fresh launch and
submitting the dependent finite teacher job. Existing bindings and outputs
are never overwritten. The original run used the equivalent private bounded
driver; the public launcher's job/node arguments replace those operational
identities, without changing source generation, labels or selection rules.
