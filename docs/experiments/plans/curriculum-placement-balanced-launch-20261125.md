# Finite placement lifecycle with unchanged retained numerical criteria

An actual qualified balanced2472 -> yaku2500 parent and complete57-source
placement preparation are prerequisites. They are not currently available.
The new lifecycle entry is prospective; software binding never starts a fit.

Submit all six phase jobs held, check their actual identities/resources and
dependencies, then bind immutable source/admission files and release the chain:

| Phase | Finite GPU allocation | Dependency / behavior |
|---|---|---|
| Register |35m,1 GPU,4 CPU,48G|Seal actual final3B and register the unchanged full-data budget|
| Integration |40m,1 GPU,4 CPU,48G|After successful registration; isolated actual two-update control|

| Fit |24h,1 GPU,4 CPU,48G|After successful preparation; complete registered two epochs|

Foreground timeouts stay below scheduler limits; TERM/INT produce nonzero
receipts. Failed dependencies are canceled; unsuccessful partial submissions
cancel only their own jobs. No polling process, CPU-only allocation, silent
restart, optimizer resume or production release is introduced.

The preparation function retains every original numeric condition. Adapt only
its explicitly bound actual integration-job ID, producer/receipt paths, retained
loss summarizer import and retained-launch status. Add the new loss/lineage
requirements, preserve all old57-source/tensor/optimizer/objective checks, and
bind current queue/config/source identities before optimizer updates. Do not
change original development criteria in response to future results.

Each successor saves its predecessor's genuine terminal before doing long
work. A separate five-minute parent-terminal job must be queued while3B is
actually running, after its own capture job; it preserves that capture's real
terminal even if data preparation takes much longer. It does not start training.
An expired uncaptured record is refused, never reconstructed from an intention.
Submit placement later only when both actual qualified parent and full data exist.

For a fresh checkout, run the batch entry with phase`bind` in a finite GPU
allocation. It creates missing software-only prerequisite bindings by running
their tests, or verifies/reuses existing immutable bindings; then binds the
lifecycle. Actual data/parent and two-update integration are still mandatory.
All research output remains isolated. Independent unopened v8 confirmation
and complete final source closure remain separate unfinished requirements.
