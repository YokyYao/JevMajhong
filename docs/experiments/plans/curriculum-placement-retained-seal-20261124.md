# Qualified retained3B parent seal for placement training

This separate producer closes the gap between the retained3B evidence and the
already implemented retained-placement parent verifier. It accepts only the
fixed retained3B lineage, actual registered final2500, all182494 exposures,
24516 serving reloads,376 optimizer states and the original successful3B grade.
Actual prepare/fit/audit exits, queue job identities and the capture job's own
archived successful terminal/receipt are all mandatory. No terminal is invented.

The child data must be the completed57-pool placement corpus with fixed80/20
source masses, exact inherited replay, current family membership, materialized
exposures and prepared two-epoch orders. Original and expanded files are
verified. Every parent TRAIN/validation row must match the declared placement
instruction projection; state, labels, targets, metadata and menu order remain
exact. Validation stays unexpanded. Recovered data additionally bind the actual
full-projection producer lineage. No missing pools are imputed or renormalized.

The actual audited final2500 model and policy identities, frozen Qwen base,
runtime, source/data hashes and original grade enter the new immutable seal.
The seal explicitly names the retained parent loss and normalized-alignment
child loss. It preserves the new placement public-input/execution contract;
parent native games cannot substitute for the child's new actual step0 games.

Software checks do not create this seal or qualify any future parent. The
producer is intended to run in a finite scheduler GPU preparation job only
after genuine parent completion and full data/exposure preparation. It neither
loads a policy nor launches/registers training. Fourth-course registration,
real tensor/input integration, original development gates and the unopened
final comparison remain separate requirements. Raw records stay private.
