# 当前切分与历史来源字段分开处理

第四阶段新曝光/验证入口的实际数据接入发现，旧回放保留了来源的 `_meta.split`，
这个字段不能直接作为当前课程的训练/验证归属。原始来源对象保持不变是已有回放的设计，
当前归属应由冻结的课程文件、成员和家族划分确定。

在 GPU 作业 318979 中实际扫描完整 3B 回放，结果如下：

| 当前文件 | 记录数 | 来源字段 train | 来源字段 validation | 未提供来源 split |
|---|---:|---:|---:|---:|
| TRAIN | 91,247 | 90,746 | 0 | 501 |
| validation | 24,516 | 5,146 | 19,151 | 219 |

两个当前文件的 ID 交集为 0、家族交集为 0。
以上是成员和家族核查，不是仅凭来源标签判断存在泄漏，也不是新增全量策略评测。
现有 3A/3B 的数据、配方、模型参数和运行作业没有被此修正修改。

## 后续训练入口使用的接口

`tools/curriculum_placement_partition_v1.py` 承接已有曝光/指标模块，修正直接依赖来源 split 的假设：

- `membership` 从两个完整当前文件生成私有成员清单，记录唯一 ID、原始完整对象指纹、
  文件内顺序、家族和来源字段统计；拒绝跨文件 ID/家族交叉、重复或已扩展记录。
- `require_partition` 检查实际记录身份、内容和顺序与已绑定清单一致。
- `expand_train` 使用经验证的当前 TRAIN 归属调用已有曝光实现。
  输出仍保留全部原始对象；新副本恢复完整原始元数据，只添加原先声明的副本 ID 与曝光追溯。
  来源 split 缺失或与当前切分不一致都不会被静默改写到训练文件。
- `profile` 先验证当前 validation 成员，再生成临时验证视图供已有指标实现使用。
  视图明确记录原来源 split 的值/是否存在和当前归属，公开模型输入与监督不变。
  来源记录不修改，训练成员或曝光副本不能冒充验证记录。

成员清单必须与实际两个数据文件及代码哈希一起冻结；单独传一个未经绑定的字典不能作为审计证明。
当前完整 3B 回放的实际兼容性证明已通过：所有原始对象指纹保持、临时验证视图的全部状态和监督保持。
四项合成测试另行验证来源字段与当前归属区分、交叉和改动拒绝、验证适配器、曝光后原始元数据恢复。

该证明不覆盖尚未完成标注的全部第四阶段 57 来源，也未运行完整新验证 profile。
等 data3 和配比准备成功后，最终训练登记必须使用上述成员接口，
不能直接对原始课程回放调用仅检查 `_meta.split` 的早期曝光/指标入口。
旧实现、原始文件和既有证明保留，当前训练继续按固定预算推进。
