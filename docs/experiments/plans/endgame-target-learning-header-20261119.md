# 第十二轮之后：目标学习与说明文本诊断

第十二轮在 72 步早停、未通过旧 43 个第四名脱四检查，正式 v8 不变。新增终局监督与明确目标仍未带来合格候选，下一步先诊断，不登记新训练、不延长失败权重。

固定使用现有第十二轮 55 个普通第四名训练局面和全部 186 个验证输入，原分组、有限终局标签及正式原策略参考缓存均不变，不挑选收益更大的案例。冻结来源、预测缓存、权重、库和代码后，在一个有时限、日志、退出状态的 Slurm GPU 作业内完成以下工作。

1. 复用第 0 和 72 步的全部验证预测，重算旧 43、新 8 脱四及第三名、守位检查，按动作类型汇总分歧。验证预测不重跑，不把失败案例加入训练。
2. 分别用正式 v8 和本轮第 72 步权重，预测相同 55 个训练输入，合计 110 次查询。对比原策略缓存、当前输入路径、训练后选择和 19 个明确改进目标；报告目标 CE、目标首选匹配及有限终局估计，判断监督是否真正学到。失败权重仅供研究，不作为教师或候选发布。
3. 对正式 v8 做**单一说明文本消融**：全部 186 个验证输入只把问题说明换回逐条原教师请求的说明，当前公开状态、计分特征、候选和服务动作范围完全保留。在开始消融前，固定哈希选择 8 个当前原输入重复查询，必须与第 0 步缓存精确匹配（浮点容差不超过 1e-7）；否则停止，先排查重放差异。

说明文本消融 186 次、重复控制 8 次，加训练查询 110 次，总预算 **304 次模型查询、零参数更新、零新增对局模拟**。原教师说明必须由原请求重建并核对缓存中的教师摘要和有序动作支持，不能临时改写文字或按结果搜索提示词。

这些是已用数据上的机制检查，不是新的强度确认。必须同时保留旧 43／新 8 分层、原专家 CE 和原生策略 KL，不能只报告改善的一项。消融即使改善，也不直接发布模型；输入协议改变后的准入、重新训练和完整比赛验证需另行登记。

本诊断不启用第十三轮训练、独立评测或导出，后续仍按原训练目标及登记方案推进。只公开代码、方案和聚合结果；原始输入、动作概率明细、逐场记录与权重不公开。
