# 从预训练 base 训练统一麻将 LoRA

现有数据已经分类、去重和选择来源，**Jev Balanced Base LoRA v1 已启动实际参数训练**。本轮使用固定 Qwen/Qwen3.5-0.8B（2fc06364715b967f1860aea9cf38778875588b17），新建LoRA与动作指针头，冻结预训练主体，统一学习普通出牌、立直、吃碰、三种杠和跳过。启动审计确认LoRA B从零开始、A非零，旧麻将适配器未加载，预训练主体无梯度；8次实际更新后LoRA B和动作头均发生改变。没有新增外接决策修正网络。

## 分类、来源和标签

71组来源中，68组完成、3组未完成。逐条索引550272行、336615种公开请求；其中包含视角、修订与动作分支重复。它们不能直接相加作为独立训练样本。索引和原始文件私有，原文件只读。原生验证分片和封存测试文件在首轮分类中不打开，历史保留组由来源元数据全局登记；训练池构建阶段才有计划地读取指定验证来源，测试文件继续封存。

分类器曾把加杠`consumed`误当作新消耗的手牌数量。实际MJAI里它是旧碰的三张牌，新加的一张在`pai`。原索引保留，独立复核6586行格式标记，修正900行；剩余5686行不直接准入。修订不能改变奖励、原始轨迹或历史保留组。

质量池选择5组已修复专家牌谱来源、7组独立审计过的模拟来源。合并重复位置，隔离14个专家标签有冲突的位置。纯专家标签来自确认修复了候选消耗牌、宝牌前缀和不可观测跳过问题的链路；未确认的派生语义不会自动作为新证据。池中含77697个训练候选位置和1499个验证候选位置，训练／验证没有组交叉。原目录数量、扩展分支数和未来模拟次数均不当作独立位置数。

模拟目标沿用`own_win + .25*discounted_speed - 2*dealin`，分数权重为零；正效用但降低和牌机会，或同等机会却更慢的正向鼓励被归零。使用温度0.05的收益软目标，不叠加旧模型近零的鸣牌先验；这不是固定鸣牌奖励，全部负效用动作仍参与比较。

旧模拟所谓完整菜单，是PolicyAgent筛选后的`eligible`子集。471个模拟局面仍有合法动作缺少收益标签。第一份池构建在此被保护检查拒绝，失败输入私有保留。修订后的训练保持完整公开输入菜单，**对模拟样本只在已评估动作上归一化损失**；未知动作的零目标是掩码，不是负标签。专家交叉熵仍覆盖完整菜单。训练与验证均使用同一掩码定义，不能直接用上游默认损失训练这份数据。

## 训练与阶段目标

LoRA rank16，LoRA学习率2e-5、动作头1e-4，权重衰减0.001，dropout0.05。单卡bf16，微批1、累积16，有效批量16，梯度检查点开启；首轮1个epoch，最多1024次更新。训练参数共11347456，主体保持冻结。使用原始请求重新编码与反传，旧隐藏特征缓存不作LoRA输入。

启动前和每128步验证。选模使用门清／副露／吃碰／杠权重0.45／0.20／0.30／0.05的目标交叉熵，连续3次不改善则早停。上游落盘的硬标签基准结果保留，包装器另行保存真实硬／掩码软目标指标，并将后者用于选模；不把它们混称为比赛胜率。训练中记录真实LoRA和动作头参数更新、token准入及各阶段指标。

1. **启动目标已达到**：新LoRA初始化正确、主体冻结、16384条全部准入、实际LoRA和头部更新可见。
2. **学习目标进行中**：看分层验证曲线、吃碰及杠窗口表现，及时停止无改善的训练；不靠总一致率宣布成功。
3. **效果目标尚未验证**：选定统一模型后核验原生推理，在全新开发牌山比较自身和牌率与速度、放铳及净点，独立复算支付、棒池和名次。开发通过才进入另一组新牌山确认。

本轮同时改变数据配比、LoRA训练范围和目标构造，因此不是证明LoRA必然优于小网络的单因素实验。尚无新整场改善结论，不替换已保留参考或Windows安装包。原始数据、逐状态诊断和实验权重保持私有，公开可复用代码、配方与聚合结果。

## 完整新适配器的评测流程已登记

新增`evaluate-unified`与`audit-unified`流程。旧头部评测器要求编码器不变，不能用于本次LoRA。新流程绑定适配器权重、适配器配置、动作头、分词器及聊天模板六个文件的整体身份，并检查预训练权重、上游源码和实际训练输入回执；复算保存的验证曲线，核对最终选定的全模型检查点。训练／服务格式及损失代码必须与实际训练归档一致。

训练正常结束后串行运行零整场比赛的原生预检，逐条核对256个验证位置的概率（最大绝对误差2e-5），并覆盖门清、副露、吃碰和暗杠／大明杠／加杠窗口。当前仅完成代码、配方和作业登记，尚无实际GPU预检通过结论。

预检通过且再次核实牌山未消费后，开发使用11910000起8牌山192场；开发通过才进入11920000起32牌山768场确认。三个工作区329份实际协议（含原生采集源牌山字段）未发现这两个区间已被消费。所有参考对局重新模拟；候选只加载一份新适配器和动作头，旧双编码器及82b鸣牌修正只属于参考策略。

双方沿用相同的合法动作／牌效筛选和直接和牌规则，所以结果是该固定仿真策略协议下的比较。独立审计重新遍历MJAI，核对四家支付、立直棒池、和牌／放铳手数、速度、终局名次和完整牌山配对区间；它不宣称独立重算番符。原始评测先写待审计结果，审计通过才产生最终结果文件，避免把自检标记当成独立证据。

当前173项核心检查通过。普通出牌和鸣牌内部指标改善不等于整场改善，实际GPU与新整场结果仍需完成；原始记录和实验权重继续私有。

训练完成：1024 步，按冻结的阶段加权验证 CE 选择第1024步，CE 为1.1919（初始2.1025）。完整 adapter、决策头和 tokenizer 已通过256例实际推理一致性检查，覆盖普通出牌、吃碰、暗杠、大明杠和加杠；最大概率偏差小于1e-7。192场全新对照评估正在运行，独立计分审计已串行排队，尚无此轮 LoRA 的比赛提升结论。

### 首轮完整评估失败与第二轮修订

首轮192场（8组独立牌山）及独立事件审计完成。相对保留模型，配对和牌率变化−6.106个百分点，95%区间[−11.419,−0.793]；净得点−4201.04点／场，区间[−10194.50,+1792.42]。放铳率变化−0.936个百分点。未达到确认条件，不启动该模型的768场确认，不替换正式权重。

该模型的鸣牌数由2.5625升到3.4167次／场，但和牌率下降；立直支出由1531.25降至927.08点／场。固定验证集里，门清/副露后出牌CE仍高于旧模型，大明杠14例仍全部跳过（其中7例的有限模拟标签唯一偏向大明杠，不能视为专家真值）。这些现象支持继续检查基础决策欠训练和鸣牌先验偏移，尚未证明单一原因。

第二轮 Jev Balanced Base LoRA v2 已启动：仍从原始固定base新建rank16 LoRA和决策头，统一处理全部操作；优化器、随机种子、损失、奖励和验证集256条的字节均保持不变。训练集扩大到32768条、31670个不同局面，2169个训练组，与98个验证组零交叉。门清16384，副露后8192，吃碰6728，杠1464；专家吃/碰/跳过1075/1075/3226（约20/20/60）。模拟数据不按收益正负或最优动作筛选。杠仍只有366个不同局面，每个重复4次，不宣称增加了独立杠证据。

阶段目标：先核查所有token均入训并记录实际参数更新；每128步分阶段验证，耐心3次，单轮最多2048步；随后检查完整权重的实际推理一致性。全新192场开发评估使用11930000..11930007，只有和牌率均值为正且放铳增幅均值≤1个百分点才进入11940000..11940031的768场确认。确认要求配对和牌率区间下界为正，同时满足原风险限制。不得使用失败模型的比赛记录训练，也不挑选第256步等历史权重补做容易通过的测试。若再失败，继续定位数据/训练缺口，不能用验证CE代替比赛结果。

### 第二轮早期检查与比较限制

已核对两轮第0步的全部LoRA张量和决策头张量完全一致，验证集字节一致。第二轮在保留首轮15931个训练局面的基础上，增加15739个不同训练局面。优化器仍是AdamW，配置中的LoRA/head学习率是OneCycleLR峰值；总步数1024→2048也拉长了10%预热和后续衰减周期，每一步实际学习率并不相同，因此数据量、配比和调度时长同时改变，不能归因于单个变量。

第128步加权验证CE1.6800，第256步1.3252；首轮同阶段分别1.6457、1.3802。第128步80个专家吃碰窗口全部鸣牌、14个大明杠窗口全部杠；第256步14个大明杠窗口又全部跳过。该波动尚不支持“已学会何时鸣牌/杠”，不能挑选其中某个检查点的鸣牌次数作为提升证据。
