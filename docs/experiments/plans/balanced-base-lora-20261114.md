# 整理既有数据并从预训练 base 重训 LoRA

用户要求先分类整理已经生产的数据，再按配比重新训练 base 模型的 LoRA。采用固定版本 Qwen/Qwen3.5-0.8B（2fc06364715b967f1860aea9cf38778875588b17），新建 LoRA 和动作指针头，冻结预训练主体；不加载既有麻将适配器或外接决策修正网络。最终候选统一学习合法菜单里的普通出牌、立直、吃、碰、三类杠和跳过。普通动作与鸣牌同时验证，避免专项提高但整体退化。

## 当前已完成

元数据盘点发现71组数据：22组牌谱JSONL、49组原生采集／配对未来标签；68组有完成标记，3组尚未完成。牌谱训练文件合计约1.10GB，含修订、复用与视角扩增；原生来源声明共37035行，也含相同局面的不同动作分支、首轮与扩展版本。不能把这些相加当成独立训练样本。25组已完成原生来源能找到独立数据审计回执，回执存在也不等于自动允许训练。

已实现可复用的`tools/data_catalog.py`，对原始文件只读，输出私有SQLite索引和来源清单。156项核心检查通过，覆盖视角去重统计、跨集合隔离、候选消耗牌格式、模拟分支与专家标签的区别。逐条索引已提交CPU作业，等待当前整场评估及独立审计结束，保持最多两项自己的作业并发。

旧杠牌扩展小网络的三个尚未运行的拟合下游已经取消，原始登记保留。正在运行的整场评估和杠牌数据采集继续完成；不再以继续叠加小网络作为下一主线。

## 数据分类与隔离

- **专家牌谱监督**：核对来源、修复版本、合法菜单与真实可观测的跳过动作。旧候选重建有缺陷的版本先隔离，不能直接当专家标准答案。
- **模拟收益标签**：按同一局面、同一完整菜单聚合共享未来。分支`action`只是被模拟的动作，不是正确答案；未来次数也不是独立训练局面数。保留收益为负、应该不鸣牌的局面。
- **无标签原生窗口**：只计覆盖，不能把旧模型动作直接当专家标签；若用于策略蒸馏，必须另行登记。
- **视角与修订**：原生／截图视角、修订版、不同采样未来分别记录。同一实体决策的变体不能跨训练与验证。
- **局面分类**：门清出牌、副露出牌、吃碰窗口、杠窗口、和牌窗口；同时统计合法菜单和实际观察动作。鸣牌后的出牌只有来源能证实时才单独标注，不能把全部副露出牌等同于鸣后首打。

原牌谱比赛ID和模拟完整牌山是分组单位。已作为验证或测试的组在全局阻止进入训练，包含来自未完成或已隔离数据版本的历史保留组。封存测试JSONL及原生验证分片不打开；先由来源元数据登记保留组。缺少可靠分组元数据的来源不会自动获得训练准入。原始轨迹、索引、逐状态诊断和实验权重保持私有。

## 配比在去重与质量分级后冻结

先报告每类独立局面数量、有效专家标签数量、完整模拟菜单数量、截图变体数量和可保留反例数量，再确定最终混合预算。按局面窗口采样，不把“出现吃／碰／杠按钮”改成“必须鸣牌”。专家监督与模拟软目标分层记录损失，稀有杠局面有限重复，报告独立数量和有效重复次数，避免小样本被无限放大。整体出牌、门清转吃、役牌碰、已副露续打、三种杠与跳过都应有覆盖。

当前尚未冻结最终比例和训练步数，不能在逐条统计之前声称配比已经合理。后续由真实覆盖确定一份配方，先做单一路线的LoRA重训。

## 训练与验证

LoRA参数会改变编码器输出，因此使用原始公开请求重新分词、前向和反向传播，旧模型的隐藏特征缓存不能用于替代LoRA训练。上游JevAny训练器支持专家硬标签和显式软目标，可以复用其训练机制；需要新的数据清单、初始化审计、token准入和训练中分层验证，不能复用旧权重作为“从base重训”的起点。

训练前验证新LoRA初始化、主体参数冻结、候选及标签不泄漏到输入、训练／验证组不重叠、token预算不静默丢数据。先做短运行确认有效梯度和吞吐，再按实际数据规模登记完整预算，训练中定期验证并保存检查点。验证损失或一致率用于检查学习情况；策略采用仍以全新模拟的自身和牌率和速度为主、放铳为约束、净点为辅助，不能用高一致率代替比赛改善。

新模型需要原生推理核验、固定权重的新开发牌山及独立结果复算；通过后再使用另一组新牌山确认。既有开发和测试结果不能作为新权重的评测。没有通过这些检查前不替换已保留参考或Windows安装包。
