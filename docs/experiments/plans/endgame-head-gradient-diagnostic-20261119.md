# 完整混合训练集的原头梯度诊断

第十四轮冻结编码器后，关键训练目标命中从 0/19 到 4/19，但 32 步时守位、原生第四及第三名验证退化，选中 0 步；停止时只见过 512/905 条记录、19 个严格改进例子中的 11 个，前 8 次更新完全没见过这些严格改进例子。不能据此宣布数据不够、容量不足，或认定增加轮次必然有效。

本诊断先量化现有混合损失与训练顺序，不训练第十五个候选、不改标签、不放宽守位约束。

- 只使用既定 905 条训练记录；79 条损失为零的固定和牌对照不产生梯度，826 条正损失记录全部纳入，不挑有利子集。
- 从正式 v8 获取实际原头的 FP32 输入。显式复用已经核验的 19 条冻结表示，另外 807 次实际编码；缓存新输入及顺序候选、实际概率、输入哈希、权重身份及依赖版本。逐条头部重放须与端到端一致，55 条已有 v8 预测作为额外控制，容差 1e-7 且首选翻转为零。
- 用实际第十四轮保存的 `trainer_state.pt` 顺序及曝光账本交叉核对前 512 条记录。报告每 8 步各来源曝光及按登记权重计算的损失质量，保留前 8 步严格来源为零的事实。
- 在正式原头和已保存的第 32 步原头上，分别计算每个非零来源的平均 CE、梯度范数及两两余弦；按实际来源损失质量合成全训练集梯度，计算它对每个来源损失的一阶方向。另对前 32 个真实 batch 的组成计算**均在初始 v8 参数处**的梯度方向与全量方向的偏离，不能将其称为真实变化参数的训练轨迹。
- 同时报告归一化 SGD 方向及带已登记裁剪、epsilon 和权重衰减的首步 AdamW 方向的一阶内积；它们只衡量局部损失方向，不证明有限更新或麻将胜率变化。零梯度余弦记为未定义，不伪造为冲突。

编码器与源权重只读；计算 `autograd.grad` 后丢弃梯度，不创建优化器、不修改模型参数。全部依赖、数据、特征缓存与正式权重前后核对；验证、开发和独立模拟均不使用。结果决定后续是否需要分层曝光、全量稳定梯度或目标约束，而不是预先认定梯度冲突存在。缓存表示为私有可复用工件，不是额外部署网络。

全部计算在有 GPU、配套 CPU、时限、日志和退出记录的调度作业执行。只发布方法和聚合结果。
