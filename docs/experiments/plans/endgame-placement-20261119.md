# 末盘追分与守位：新增训练要求

登记日期：2026-11-19。状态：需求与训练设计，尚未修改生产策略、生成新标签或启动训练。

## 目标与行为

面向四人东风，在每局结算后记录四家实际分数、顺位及下一局场况。进入可能结束整场的末盘时，策略须根据当前顺位和分差决定是否追分：

- 第三名：优先寻找进入前二的可行路线，识别“能和但仍第三”和“足以反超”的区别。
- 第四名：同时评估脱离第四、进入前二的机会与代价，不因前二难以达到而放弃可行的脱四路线。
- 第一、第二名：保留守位对照，避免追分训练导致领先时无条件做大牌或拒绝足以结束比赛的和牌。
- 追分应影响此前的弃牌、吃碰、立直、做役及攻守选择，不只在出现和牌按钮时才处理。

“需要更高打点”取决于真实结算与整场是否结束。不得实现为末盘第三、第四名一律拒绝小牌，或只要增加副露就加分。

## 分差与结算

令当前分数为 S，候选结算变动为 Δ，目标玩家为 t，自家为 p。结算后比较 S[p]+Δ[p] 与 S[t]+Δ[t]，同分按实际房间规则判断顺位。相对分差的缩小量为 Δ[p]−Δ[t]。

例：四家分数按当前顺位为 32,000 / 25,000 / 22,000 / 21,000，自家第三，非庄，无本场与立直棒；假定此次和牌会使整场结束：

| 候选结果 | 自家 / 原第二名结算后分数 | 结果 |
| --- | --- | --- |
| 向其他玩家荣和 1,000 | 23,000 / 25,000 | 仍第三 |
| 直接荣和第二名 1,000 | 23,000 / 24,000 | 仍第三 |
| 直接荣和第二名 2,000 | 24,000 / 23,000 | 反超至第二 |

自摸须比较四家的实际付款，本场、立直棒、庄闲、多人和牌、流局罚符及同分优先顺序均应交给规则结算处理。“东四”不能直接等同于必然结束：连庄、延长和终局条件必须与实际东风规则一致。

直接荣和目标玩家只是一种可能的结果。出牌时模型不知道谁将来会放铳，不能把预想的付款对象当作已知输入。

## 当前实现缺口

已检查的主分支以 Jev Play v2 为基线：

1. `core/state.py` 与桌面 `engine.py` 已提供四家分数、场风、局数、本场和立直棒，但没有完整的局间分数轨迹或明确的末盘追分状态。`hand_number` 当前有按庄家位置推导的路径，须先核对它与原生局号、座位映射及客户端显示的一致性。
2. `training/futures.py::finish_intervention_hand` 在干预局结束后停止，不能为连庄或延长后的最终顺位提供标签。发布模型的模拟奖励为自己和牌、速度与放铳，不是整场最终位次。
3. `desktop/jev_sidecar/engine.py::recommend_reaction` 在存在 `hora` 时直接优先和牌，不经过模型比较。因此只重训权重不能使工具学会必要的拒和。
4. 现有整场评测已输出最终分数、名次与结算账本，可复用，但不能替代新增末盘专项数据与拒和闭环检查。

这些是已观察到的实现缺口，不表示已确认现有模型在所有末盘局面都会作出错误选择。

## 数据与信息边界

先实现局间账本：按对局、局号与本场记录四家结算前后分数、分数变动、立直棒池、庄家、下一局或整场终局标记。以结算事件和下一局初始分数交叉核对，处理多人和牌、流局、立直押棒与跨帧重复。桌面应保存连续场况；中途接入仍允许用当前可信分数决策，不虚构缺失历史。

策略输入只包含决策时已经公开的信息。整场未来结果只用于训练标签和离线评测，不回填当前观察；未知暗手、牌山和实际未来放铳者不得进入输入。

新增训练位置按以下维度分层：

- 当前顺位、到第二名与第三名的分差；差距不足、临界、明显不足及超额打点。
- 庄闲、局号、本场、立直棒、可能连庄或延长、同分结算。
- 门清与副露路线、立直与不立直、吃碰后打点不足或仍足够。
- 和牌与跳过同时合法的真实窗口，以及追分前的普通弃牌和鸣牌窗口。
- 领先守位与非末盘回放对照，保留原有吃碰及三种杠覆盖。

使用合法原生回放或可复现的规则引擎状态生成；不拼接无法由规则产生的分数、手牌与场况。按来源对局／牌山组划分训练、验证和独立测试，同一公开局面及其备选或共同未来不跨集合。

## 标签、奖励与续训方案

从已发布 Jev Play v2 的同一套 LoRA 和动作头续训，不为本需求额外叠加修正网络。

新增末盘标签须从同一公开局面比较实际候选，并续打到规则引擎确认整场结束。各候选使用配对的未来随机性；遇到连庄或延长继续采样，达到资源上限的截断记录不得伪装成完整终局标签。标签依赖隐藏状态与续打策略的偏差仍需记录，不能当作专家答案。

候选效用以真实终局顺位为主。首轮小试可登记一个单调的终局位次效用，例如第一／二／三／四名为 1 / 0.5 / −0.5 / −1；该数值是待验证的设计，并非麻将规则或已经有效的奖励。前二率、脱四率、净得点及放铳率分别报告，不用每次和牌固定奖励盖过终局目标。具体效用、混合比例与风险限制须在小试训练前封存。

新增数据优先补足末盘追分和守位的缺口，同时回放原有数据；不以复制少数“拒绝小牌”案例充当覆盖。先做一轮小规模分层标签与拟合诊断，再决定扩大采集和训练预算。持续观察原有出牌、吃碰、杠与非末盘决策是否退化。

## 工具与规则同步

和牌／跳过须进入可学习的合法选择路径，再同步训练、模拟与桌面服务的候选语义。拒绝荣和可能造成临时或立直后的振听，必须由规则引擎沿后续轨迹生效；不可把拒和后的状态仍当作随时能荣和。

是否拒和须比较继续比赛后的预期终局结果，而不是只比较当前牌的面值。庄家小牌连庄、足量立直棒、避免第四及继续进攻的真实成功概率，都可能使小牌和牌成为合理选择。不能先给现有 EXE 加一条强制拒和规则，再声称已经学会追分。

## 阶段目标与验证

1. 规则与输入：核对局号、座位、四家分数、本场、棒池、终局与延长条件；账本和末盘标记通过后才采标签。
2. 功能用例：覆盖上表分差、实际自摸付款、棒池补足、同分、连庄、延长、拒和振听，以及领先时应正常和牌的反例。
3. 数据与小试：核对分组隔离、真实合法动作和完整终局标签；重点观察是否能区分不足打点与足够打点，不能以“拒和次数增加”作为成功。
4. 开发对局：在固定小规模分层对照中评估末盘进入前二、脱四、守住前二、放铳和最终净得点。不见有效信号或出现明显退化即停止分析，不直接扩大轮数。
5. 独立确认：固定候选与准入条件后，才用未参与训练或选模的新牌山进行配对确认，按独立牌山组报告区间。不同初始顺位与分差分别报告。
6. 部署：确认没有被桌面“优先和牌”逻辑覆盖，真实服务请求与模拟动作语义一致，再发布新模型和工具。训练完成不等于已证明提升。

本次只登记要求和方案，不申请 GPU、不启动训练、不变更当前模型与安装包。后续计算遵守工作区集群约束：只在调度器批准的 GPU 作业内执行，不在登录节点运行计算或提交 CPU-only 作业。
