# Placement: dependent full-budget training and independent audit

The executable chain is qualified final3B parent → actual placement budget
registration → real-model two-update integration → full-course launch → final
evidence audit. Every step is a finite scheduler GPU job. No computation or
unmanaged background controller runs on the login node.

`tools/prepare_curriculum_placement_launch_v1.py` requires the actual successful
integration GPU terminal, its immutable completion binding, the saved original
parent, both376-state control optimizers and changed control adapter/head. It
reconstructs the two57-source loss observations and checks that the actual full
production order adapter executed both prepared permutations. Integration
weights are never inherited by the candidate. The candidate starts again from
the exact qualified final3B weights, with a new optimizer.

Before the first candidate update, the launch binds the budget/data identity,
integration proof, unchanged trainer/native evaluator, original prospective
assessment criteria, independent auditor, plotting implementation and scheduler
wrapper. The inherited early retention scope must contain both classes. Real
initialization checks and a fresh64-game child-policy baseline still occur
inside the full fit before updating. Existing parent games cannot become zero.

`cluster/curriculum-placement-course-v1.slurm` runs launch preparation and the
full two-epoch fit in one20-hour GPU allocation. The actual count-derived
budget remains unchanged, with five loss/game curve points and no noisy
intermediate early stopping. Failures produce a phase-specific exit receipt;
outputs and an existing launch are never silently overwritten or resumed.

The separate audit allocation has a two-hour limit. It archives actual fit
terminal evidence and independently reconstructs exposures, loss components,
unique validation predictions, final serving probabilities and full native
ledgers. Successful evidence verification and the numerical development grade
are reported separately. A failed development grade is preserved as failure,
not converted into a passing result. Dependent jobs use the scheduler's
`--kill-on-invalid-dep=yes` so a failed prerequisite cancels their dependent
work without leaving an unmanaged polling process.

The final independent v8 confirmation grid remains closed. No part of this
chain replaces main, the released model or Windows packages, or publishes raw
private records. At implementation time the upstream data/parents/integration
are still pending; a queued fit is not a claim that training has started.
