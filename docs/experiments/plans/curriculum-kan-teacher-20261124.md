# Actual public-history teacher choices on the kan-source pilot

The source-only pilot completed189 of192 preregistered native opportunities:
141 TRAIN/24 families and48 validation/eight families. Three TRAIN kakan
prefixes that would decline a legal win were quarantined without replacement.
The admitted source opportunities cover TRAIN48 ankan/48 daiminkan/45 kakan
and validation16 of each operation. Every source's exact native prefix,
public request and complete legal menu reproduced in an independent replay.

The teacher collection keeps all189 source opportunities and their original
whole-family partitions. It uses the same pinned Mortal-298k source actor,
weights and native action mapping as prior teacher data. A fresh Bot receives
the actual complete, correctly redacted public prefix for its own observer;
the hidden source wall, opponents' initial hands/draws and construction motif
never enter that history. The replayed own-hand mirror must match the native
hand. Chi/pon and all three kan legal flags must match the native menu for
every source before accepting a label. An inconsistency fails collection.

Only the current teacher choice becomes a hard label. Scripted prefix actions
are not supervision. The source actor's forced legal wins are recorded
separately and excluded from teacher SFT, preserving its existing behaviour.
Every other choice must map uniquely to an actual physical legal candidate
and be submitted to the native engine. Simultaneous higher-priority actions
can supersede an observed call intention; submitted intention and resulting
native events are preserved separately.

Keep all actual teacher choices, including skips, uncertain or apparently
unhelpful ones. Do not replace source cases to obtain positive kan labels.
Report selected-versus-other counts by offered kan type and source motif.
These are static teacher decisions, not sampled action advantages, expert
optimality or a student's improvement. A shortage of positive teacher labels
must be reported rather than corrected by prescribing the target operation.

The finite GPU job uses one allocated GPU/one companion CPU, a10-minute job
limit, an8-minute process limit, logs and an exit receipt. Collection is
scheduled after the currently running3A fit terminates; it does not edit that
fit, reserve additional GPUs outside scheduler limits, admit a3B parent or
replace a published model. No student optimization occurs. Full cross-corpus
overlap, normalization/encoder checks, conditional-world action comparisons
and a new registered data/mixing recipe remain separate prerequisites for
any future use in training. Raw source cases and labels remain private.
