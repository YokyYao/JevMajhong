# Final confirmation seal after the actual early-route curriculum

The active course uses basic608 → calls388 → selected3A1800 → 3B2500 →
the full registered placement budget. This source adds the final registration
producer for that route. It does not admit the currently running 3B model.

The sealer consumes the actual completed placement registration, full-budget
completion, independent execution audit and original development qualification.
It derives both parameter bundles and policy identities from their real files.
The candidate is the registered final placement step, never the minimum-loss
checkpoint or an intermediate development winner.

Complete final-candidate source evidence is a separate prerequisite. Its actual
producer must bind the proof, producer sources and every classified artifact in
an immutable completion receipt. The already completed snapshot250 closure is
reusable ancestry evidence, but cannot be renamed into a final source proof:
actual final3B and placement sources, datasets and source families remain to be
joined after they exist. Missing evidence leaves no final registration.

The exact criteria in `configs/training/curriculum-confirmation-final32-v1.json`
are the previously registered joint-primary criteria, not a new statistical
target. There are 32 untouched logical seeds × four seats × two opponent
profiles, for 256 complete East matches per policy and 512 total. Candidate and
frozen v8 share rules and cells. Top-two rate and net points are the two primary
outcomes; all secondary outcomes and any tradeoffs must be disclosed. No adaptive
extra games, seed substitution or automatic model release is permitted.

The reference anchor must be an existing consumed-development native match
record. Both old and explicit-event loops return the same complete row schema;
the frozen reference adapter ignores the added event argument. The actual final
runner still reproduces the entire anchor row with frozen v8 **before** opening
the reserved seeds. Schema compatibility alone is not an empirical reproduction.

Run the sealer only in a finite allocated GPU job, with logs and an exit receipt:

```bash
.venv/bin/python tools/seal_curriculum_confirmation_early_v1.py \
  --provenance /absolute/path/to/actual-final-source-proof.json \
  --reference-development-anchor /absolute/path/to/consumed/reference/matches-private.jsonl
```

The existing early-route consumer verifies the complete proposed registration
before any seal is written. The sealer never loads a model, trains, generates a
game, submits confirmation jobs, changes an existing source binding or overwrites
a complete/partial final seal. Actual reserved execution and the independent
post-run audit remain separate finite scheduler jobs. Raw records stay private.
