# Complete-world recovery to full placement data

The v3 adapter connects complete-world recovery to the original fixed108-view
merge and placement input projection. It accepts the original completed shards,
v2 complete-case recovery and v3 complete-world recovery. Every shard still
requires all27 selected views labelled or explicitly quarantined, the frozen
teacher, original family partition and actual writer terminal evidence.

The full v2 merge/prepare function code objects are reused with isolated global
namespaces. The original merge changes only its assembled root; the original
projection changes only control/input and output paths, verified by reversible
AST substitution. Neither source is edited. New outputs are distinct from all
original or v2 outputs.

A v3 recovery lineage additionally binds its actual prior exit receipts,
whitelisted Slurm producer commands, immutable complete-case admission and
production complete-world cache manifest. The cache identity must match the
original collection, teacher and frozen v3 entry. Every referenced completed
world file must retain its original hash. The software-proof cache has a
different purpose/identity and is rejected. Partial targets remain excluded.

Seven focused tests cover unchanged full pipeline code objects, reversible
source-path substitutions, original full-shard validation, successful v3
lineage, changed/missing cache provenance and rejection of live/unknown prior
writers. A finite allocated-node binding checks frozen sources and rejects the
actual incomplete original shard. This is readiness evidence, not an actual
full-data merge, input audit or fit admission.

No pipeline or recovery is launched by binding. Later merge/prepare jobs each
have a one-hour GPU allocation,55-minute subprocess limit, logs and exit
receipts. Full57-pool coverage, mixture/exposure preparation, qualified parent
and real model integration remain prerequisites for fourth-course training.
Only source/plans and aggregate evidence are public; raw records remain private.
