# Fresh native win/riichi and win/kan source families

Existing reused terminal controls had9 TRAIN win/reach windows but no held-out win/reach or current win/kan offers. The new source generator targets those gaps with actual RiichiEnv transitions and complete physical136-tile walls, never by adding synthetic legal flags or labels to a JSON request. It creates a delayed dealer self-draw in East4 after a real initial discard and intervening opponent turns. Open kakan sources first execute a native pon and mandatory discard; pon resets the turn, so three subsequent opponents draw before the caller's next draw. These are deliberately constructed conditional opportunities, not natural-game frequency samples or a strength benchmark.

Before native collection or any teacher value, generate36 distinct canonical14-tile families:8 TRAIN and4 validation for each of win/reach, win/ankan and win/kakan. Suit permutations and rank reflections share one canonical family. Each family has three public score contexts (hold second, third gap3000, fourth gap5000), producing a planned72/36 views. All score variants share the same partition and source wall. Source early-opponent wins or unavailable target windows are explicit construction quarantines; no future-value-based replacements are allowed.

Every admitted row is reconstructed from its complete native physical trace. Opponents must never have declined a legal win; known observer choices remain in cloned state. The public request contains only its own hand and ordinary visible information plus the verified current public win source. Full walls and traces remain private metadata and never enter model input. Native one-forward accept and special-action checks, actual encoder mapping, opposite3B exact public-input/group exclusions and source-family split checks precede data admission. At least two actual validation families per operation are required; counts must be reported rather than assumed from the plan.

The generator produces UNLABELLED source rows only. These are not expert decisions or fixed should-kan examples. Public-world paired complete-match search, bootstrap uncertainty and actual student/native evaluation are still required before using them for training. The source list, data mix, eventual fit and final untouched v8 comparison remain separate. Existing training, source corpus and production/Windows models are unchanged. All work runs in bounded scheduler GPU allocations; only source/plans/aggregates are public.
