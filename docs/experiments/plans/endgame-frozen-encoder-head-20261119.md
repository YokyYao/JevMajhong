# 第十一轮预登记：固定编码器，只训练现有动作头

参数归因检查显示，第十轮已保存的头单独移回旧编码器尚未改变汇总位次指标，编码器更新引起更大的偏好变化，而两者联合又存在交互。因此本轮测试“现有v8特征是否能由动作头学会末盘条件决策”，不假定头训练一定有效，也不将互换后的参数组当成合格模型。

从正式v8 final2088初始化同一套编码器、rank16 LoRA与动作头，**冻结编码器和LoRA全部参数，只更新已有动作头**；没有新增修正网络或额外运行时推理。冻结编码器在训练前向中保持eval模式，关闭LoRA dropout造成的特征随机变化，动作头保持训练模式。优化器只能包含动作头；既要证明头发生真实更新，也要证明LoRA在实际训练及最终检查点中保持原张量。

保持第十轮905条训练／186条验证、全部来源划分、输入格式、标签、终局效用及损失配比，不增加数据或重算模拟。原1,091条冻结参考须在权重、请求及动作顺序一致后全部复用，预计新增教师查询为0。数据准入时核对全部905／186条身份、输入、标签与目标和第十轮完全相同。

动作头学习率固定2e-5（第十轮为2e-6），新建优化器；底座／LoRA学习率字段不用于任何实际可训练参数。提高现有头的更新速度是本次对照的一部分，不能由此将结果单独归因于冻结。有效batch16，两遍数据，实际最多114步，每8步验证、耐心2；关键来源完整唯一曝光前不能选非零候选。仍允许原有能力保护触发更早停止，不延长为额外遍数。

原专家CE、原参考KL、领先／落后普通上下文KL分开检查，原CE增幅0.10、原KL增幅0.05、两组上下文各绝对KL0.05保持不变。第三名追前二、第四名脱四、普通第三名与守位保护及约束优先选模保持第十轮。原选择与提前停止机制本轮不修改；连续偏好变化不替代实际首选／终局条件。若没有合格步骤，保留正式v8，不将不合格最后一步作为部署成果。

公开配置 `endgame-placement-v11.json` 保持参考准备与拟合未启用。源码检查和GPU准备核对通过后，依次在有时限、日志和退出状态的调度作业内启用私有阶段。训练后额外核对各保存检查点的LoRA均等于v8，随后只有合格非零候选才进入已消耗开发池的候选续打；独立确认、完整开局回归及真实导出权重桌面检查仍为后续要求。只公开代码、方案与聚合结果。
