# Executable final512-match consumer; registration still pending

`tools/run_curriculum_confirmation_v1.py` executes the final comparison only
when supplied an actual final seal. It rejects statistical plans, ordinary
training registrations, partial curricula, a failed original placement grade,
changed policies and the earlier preliminary JSONL probe. The future complete
source-audit/registration producer is still required. No valid final seal exists
and the scheduler wrapper has NOT been submitted at this snapshot.

The consumer rechecks the actual full-placement completion/audit, registered
final checkpoint, parameter and policy identities, fixed reference v8 identity,
runtime package/environment versions and bound source artifacts. Actual
candidate and reference training lineages must match the expanded provenance
receipt; ancestral JSONL inputs cannot escape its catalog. JSON artifact
classifications and their actual producer/files must also be bound. The old
556-file probe cannot be relabelled as this receipt.
Both model loaders use the actual registered pretrained-base directory and
revision, rather than an unrelated inherited environment override.

The reference uses the original guarded PolicyAgent through the one-call
explicit-event adapter. Before opening any reserved game, it must exactly
reproduce an already consumed development match, including native events.
The candidate uses its sealed placement policy. Both use the same full-East
loop, seed transform, seats and opponent profiles. Each role runs the exact
32×2×4 cells, reference first and candidate second, with no optimizer updates.

Raw records stream privately after each complete match. Progress exposes only
role/count/time, with no intermediate strength summary or candidate selection.
There is no automatic retry, seed replacement or overwrite of a partial run.
A failure needs explicit inspection/recovery with its original records intact.
Model files, source inputs and registration identity are checked again after
outcomes. Output directories cannot be nested inside models/training/runtime.

Every complete role is checked with the pinned native financial functions,
followed by32-seed paired statistics and the preregistered acceptance arithmetic.
The result explicitly remains pending independent post-run audit. A successful
arithmetic result, scheduler exit, unit test or this consumer alone cannot mark
the goal complete or authorize publishing/replacing a model.

The unsubmitted wrapper has a20-hour GPU limit, foreground timeout, scheduler
log and exit receipt. It runs neither on login nor in an unmanaged background
process. Unit tests only enumerate cell identifiers or use fictitious callback
records; they simulate no reserved games and contribute no student curves.
