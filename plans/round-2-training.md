# 第二轮麻将模型训练方案

本轮继续训练 JevAny 的麻将动作评分器，重点改善弃牌决策，并检验新增训练是否能提高四人半庄的一位率。先扩充真实牌谱数据、完成监督训练与独立对局确认，再决定是否进入自博弈强化学习。

本方案基于[第一轮结果](../reports/2026-10-28-training/README.md)：整体动作一致率为 67.68%，弃牌一致率为 57.79%；约束版本一位率为 31.25%、平均顺位为 2.328，但一位率提升未通过置信区间门槛。默认策略仍为规则基线。这里的参数、数据规模和判据是第二轮预设方案，不是已经取得的结果；实际作业状态另行记录。

## 训练目标

第一目标是在固定的牌效与防守约束下，验证新模型是否比上一轮最终模型更容易取得第一；第二目标是确认其相对规则基线的优势。弃牌一致率和验证损失用于开发与选模，不能代替实战指标。

本轮继续采用有监督模仿学习。输入为玩家可见局面及合法动作，标签为真人实际选择，损失为候选动作上的交叉熵。保留现有向听、进张、现物特征及合法动作表示，不在这一轮同时改动状态编码或加入终局奖励，以便解释结果。

## 数据扩充和弃牌采样

使用已经固定版本和归档哈希的 2026 年雀魂王座牌谱，沿用 RiichiEnv 的雀魂规则重放。目标从未用于第一轮的训练比赛中生成至少 80000 条候选决策，再确定性采样 64000 条训练决策；每场候选池最多取 32 条，扩大独立比赛覆盖，避免只增加同一场内的重复局面。

| 数据项 | 预设处理 |
| --- | --- |
| 新训练样本 | 64000 条，均来自训练分组，排除第一轮已用比赛 |
| 弃牌目标占比 | 85%，目标 54400 条；不通过复制样本补足 |
| 其他动作 | 15%，目标 9600 条；保留跳过、吃碰杠、立直与和牌 |
| 开发验证集 | 沿用第一轮 1024 条、32 场验证比赛，维持原始动作分布 |
| 测试集 | 继续封存已有 1024 条、32 场；不用于采样、调参或选模 |
| 分组和去重 | 稳定的比赛哈希划分；检查比赛 ID 与局面哈希无训练验证交叉 |

弃牌占比提高属于待验证的数据配比假设，可能损害副露或立直决策，必须逐项监测。候选池若不足以满足配比，先扩大新的训练比赛候选池；达不到目标时明确记录缺口，不静默复制或借用验证、测试比赛。

数据准备输出来源版本、归档哈希、原始文件哈希、训练器规范化记录指纹、分组比赛数、各动作数量和排除原因。沿用可见牌数量守恒检查，异常整场排除；对第一轮出现较少的杠类动作单独列出覆盖数量，不把少量样本的高低准确率当作稳定结论。

保留第一轮最终权重作为冻结对照。降低学习率和增加数据同时变化，因此本轮只能评估整套第二轮配方的效果；若有效，后续再分别消融数据规模、动作配比和学习率，确认各自贡献。

本轮不自动扩大底座或增加 GPU 数量，也不启动 PPO、自博弈或在线雀魂客户端接入。资源优先用于新数据、完整验证与公平对照。

## 验证与选模规则

在参数更新前，对初始化模型跑完整开发验证，建立同一数据上的起点。此后每 400 步和训练结束时运行同一完整 1024 条验证集，推理前删除标签和元数据，使用与训练一致的上下文限制。

每次记录整体一致率、NLL，以及弃牌、立直、副露、和牌、跳过等分项的一致率、NLL 和样本数。验证集保持原有分布，不随训练的 85% 弃牌配比变化。

预先固定按完整验证集整体 NLL 最低选检查点；弃牌指标作为关键诊断，不在看见结果后切换选模标准。允许第 0 步初始化模型参与比较。连续 3 次定期验证没有至少 0.001 的 NLL 改善则提前停止，避免默认把最后一步当作最优模型。

最终汇报最后一步与所选检查点的差异。子集验证如用于快速观察，只作为监测，不与完整验证的分数混用。测试集继续保留，直到确定需要开展一次单独、不可回流调参的最终报告。

## 对照实验和四人仿真

四人半庄规则、合法动作、强制接受和牌动作以及牌效防守约束逻辑均与第一轮保持一致。每桌一个待测策略和三个相同规则基线；轮换四个座位，同一个种子对应的四场结果作为一个统计分组。

先在 32 个新种子上筛查以下四种策略，种子范围固定为 810000 至 810031，每种 128 场：

1. 第一轮最终模型，无额外弃牌约束。
2. 第一轮最终模型，加入原有牌效与防守约束。
3. 第二轮按验证 NLL 选出的模型，无额外弃牌约束。
4. 第二轮所选模型，加入完全相同的约束。

每场配对四个规则基线的对照。该阶段用于发现运行错误、明显退化和耗时问题，不能据此宣称胜率提升，也不据此更改候选模型或约束参数。若发现实现错误，应修正后重新冻结协议，改用新的确认种子。

确认阶段预先指定第二轮约束模型为唯一新候选，使用尚未用于筛查的 128 个种子 910000 至 910127，每个种子轮换四个座位。分别运行新候选、第一轮约束模型及相同种子的规则基线对照；每种模型 512 场。第一轮历史的 31.25% 不能直接作为这批新牌山上的对照值。

| 判据 | 确认阶段预设 |
| --- | --- |
| 主指标 | 半庄一位率 |
| 两个预设比较 | 第二轮约束模型对规则基线；第二轮约束模型对第一轮约束模型 |
| 区间 | 按种子聚类的配对差值 Student t 区间；每个一位率比较用 97.5% 区间 |
| 通过条件 | 两个一位率差区间下界都大于零 |
| 顺位与风险条件 | 对规则基线的平均顺位差 95% 区间上界不大于零；末位率不超过 25% |
| 未通过 | 保留现有规则默认策略，报告不确定性，不按点估计自动启用模型 |

这里的一位率按整场半庄结束后的最终结算顺位计算，不是最先出牌或最先和牌的比例。先和牌不保证最终总点数最高，单局和牌率也不等于半庄一位率。

同时报告平均顺位、末位率、每局和牌与放铳指标，以及推理耗时。得点另行报告平均终局原始点数、相对起始 25000 点的平均净得点，以及相同种子下对照策略的配对点数差和按种子聚类的 95% 区间；这些是补充指标，不改变上述预设一位率主指标及替换门槛。原始点数不换算成含顺位奖励的竞技积分。实际局数可能随策略改变，逐局指标使用各自分母。不能把 512 场当作 512 个独立牌山，也不能把这一规则对手组合上的表现换算成雀魂段位。

32 种子筛查和 128 种子确认属于顺序执行的不同阶段；确认预算不足时保存已完成结果，明确标注未完成，不把筛查样本或第一轮种子补进确认集。本轮不自动扩展到多种成熟麻将 AI；不同风格对手将作为后续泛化评估，另行冻结接口和预算。

## 资源与执行顺序

先用 CPU 重放并审计数据，完成后才申请训练 GPU，避免占卡等待数据处理。默认使用当前可用集群的 `ws-ia` 分区，Slurm 分配单张 RTX 5000 Ada；不固定其他用户的 GPU，不因检测到外部进程而终止对方任务。

主训练申请 1 张 GPU、8 个 CPU 核、32 GiB 内存和最多 8 小时。启动前检查实际分配 GPU 的 UUID、可用显存与外部计算进程。训练、验证和对局评估分阶段保存状态；超时或异常从完整检查点或已完成整场对局接续，不覆盖第一轮结果。确认评估如超过主作业剩余时间，另行排队接续，不承诺与训练主体同时结束。

执行顺序为：新数据准备和隔离审计 → 初始化完整验证 → 监督训练与定期验证 → 选择并冻结检查点 → 32 种子对照筛查 → 冻结模型的独立确认 → 结果总结。每一阶段在日志和实验清单中记录实际参数、样本数、作业编号及完成状态。模型、数据或实现与本方案发生实质变化时先更新方案，不能把变更后的结果继续标成同一冻结实验。

## 交付和后续研究

交付训练配置、数据来源和分组摘要、完整验证曲线与动作分项、所选模型文件指纹、配对仿真记录、置信区间及默认策略选择结果。原始牌谱、密钥和环境目录不进入 GitHub；新的模型权重发布时另附分片还原与完整性校验。

监督训练效果确认后，再讨论以终局顺位为回报的强化学习。该阶段需要固定奖励、混合对手池、旧策略回归测试和独立评测集，单独立项，不把第一轮或第二轮的模仿损失下降视为强化学习已成功。
