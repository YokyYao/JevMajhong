# 桌面工具策略问题：服务器交接（2026-11-09）

用户当前要求：先完成策略说明的界面设计，提交当前工具及复现信息；训练交给服务器。本机没有启动训练、没有生成新权重，也没有替换校正版2。真人第一名目标尚未达成，对局已由用户停止。

## 当前工具与设计

主窗口只显示推荐、候选、状态和两条说明：

- **整体策略**：本局牌型方向，等待摸牌和模型计算时保留，只在方向变化时改写；新发牌后清空上一局内容。
- **当前决策**：这一次打什么、弃牌后的向听/进张、听牌等待，或本次吃碰/跳过动作，每次新推荐更新。

说明由可见牌理生成，不是模型内部思考，也不另调语言模型。此前把方向与本次操作拼在一个标签中，等待摸牌时又覆盖它，现已拆开。

已实现：每秒后台窗口截图、相同决策不重复推理、Jev 启动加载与真实推理预热、前台自动点击、立直按钮与确认弃牌的两步流程、Esc 停止点击、普通五条与赤五条颜色处理、JPEG 压缩与状态去重。截图预览/区域校准仍位于设置。

点击限制：其他应用获得焦点时暂停点击，但后台识别继续；复杂多组合吃牌选择尚未支持。立直确认已在真人局两次实际执行，日志证实先点击立直，再点击原定六筒/七条，之后才确认牌离手与已立直。不能把漏识别一张灰牌当成已完成弃牌。

## 观察到的问题与已确认的接口差异

### 1. 吃碰偏好几乎总是跳过，需要区分模型问题和接入问题

真实截图读出的两个案例保存在 [`desktop/tests/fixtures/call-policy-observations.json`](../desktop/tests/fixtures/call-policy-observations.json)。它们是复现输入，不是正确动作标签：

- 可碰白的场景：原模型偏好跳过约 0.874581，碰约 0.125419。
- 可吃六条的场景：原模型偏好跳过约 0.997203，吃约 0.002797。

这些数值来自当时的桌面请求；分数、牌河等未完整保存，不能用它们要求逐位重现概率，也不能据此标注“必须碰/吃”。保持门清有时正确，单凭跳过多也不能证明策略错误。

旧监督训练确实包含鸣牌动作（见 `plans/round-2-training.md`），不能宣称当前模型从未训练吃碰。比较基准是 `semantic.py:build_request` 与 `desktop/jev_sidecar/engine.py:request/recommend_reaction`。

**接口核查结果与尚待解决的差异：**

1. 桌面请求把反应场景放在新增的 `screen_observation.reaction` 中，而 `last_discard` 固定为 `None`；训练环境提供后者。当前本机 RiichiEnv 0.4.11 的可重放观测实际输出 `last_discard=54`（实体牌 ID），不是 `{seat,tile}` 字典。截图只知道牌型，不能伪造某一张实体牌编号；需要明确约定可见牌型表示或做截图域适配训练。
2. **红牌表示已核对一致，不能误诊为冲突**：实际调用 `tid_to_mpsz(16/52/88)` 返回 `0m/0p/0s`，与桌面状态一致；MJAI 候选动作用 `5mr/5pr/5sr`，桌面 `mjai()` 也一致。这是状态与动作字段各自的正确格式，不应为修复吃碰而随意统一成另一套。
3. 桌面未完整自动读取对手立直、四家分数、庄家、场次、本场、立直棒和对手副露；部分参数沿用 UI 默认值。即使 `metadata_confirmed=False`，请求仍会带上默认的 25000 点等字段，模型可能据此作错误攻守/顺位判断。未知应显式表示，不能伪装已确认值。
4. 吃碰候选目前只传原始动作，向听、进张为 `None`，没有比较“鸣牌后最佳弃牌”的有效进张和有役路线。不过旧版 `semantic.py:features` 同样只给弃牌附加这些特征，所以不能把“没有鸣牌特征”本身说成相对旧训练格式的唯一偏差。
5. `arena.EfficiencyAgent` 的基准明确偏向门清、拒绝鸣牌。用它当教师会把“不吃不碰”再学一遍；模拟对手组合也有偏置。

### 2. 和牌动作仍有缺口

`ModelAgent.act` 在仿真中直接接受合法 RON/TSUMO。但桌面端 14 张和牌形目前只显示“检查自摸”，仍可能保留弃牌候选；按钮 OCR 还没有完整接入“自摸”。应把合法和牌动作优先处理并禁止误弃和牌张，分别回归自摸和荣和。局内尝试开启游戏原生自动和牌受到用户输入中断，**没有确认该开关已开启**，不要把它当作现有保障。

### 3. 识别与策略训练应分开

本地 `data/cua-20261109` 为压缩、去重截图及模型弱标签，未训练任何权重。每张最长边不超过 1280、上限 160 KiB；吃碰目标不明、结算动画、测试图和副露不一致样本被排除。不能把模型自己的“跳过”当成人工正确策略。

原始截图、带用户名的画面、整份事件日志和待核验标签没有提交到仓库。服务器若需要视觉数据，另行传输并审核；本次仓库中的手牌复现向量不含用户名或对局身份。

## 建议执行顺序

1. **冻结基线**：记录代码、底座、adapter、head 和运行配置哈希。先修状态编码/未知值语义，在相同合法动作上对齐原生请求与桌面请求；确认牌守恒、红牌、上家限制、食替及役的合法性。
2. **离线复现**：固定截图域案例及独立的重放观测，分别量化“原模型+旧接口”“原模型+对齐接口”。先检查是否只是接口导致偏差。不要为了让某个手工案例必吃/必碰而修改标签或阈值。
3. **补齐鸣牌比较**：比较跳过与各吃/碰后的最佳弃牌；记录向听、可见进张、确定役/潜在役、开门损失、赤宝牌、巡目、对手威胁与顺位需求。新特征的训练和推理保持一致。
4. **再做定向训练**：优先冻结底座和原弃牌评分，单独试验鸣牌评分/校准模块，或使用混合数据和约束的 head-only 更新。训练样本应来自审核过的高水平牌谱或有完整结局、可重放且配对的分支对局。反事实分支记录规则、原始种子、实体牌山、动作、续局策略及最终得点/顺位；不泄漏对手暗牌或未来牌山到输入。
5. **独立验证**：按整场/牌山分组划分训练、开发、确认集合，检查 ID 和内容哈希无交叉。吃、碰、跳过、有役与无役分项报告样本量，不能仅看总体动作一致率。使用 `seed_control.engine_seed(..., 'spaced-v1')`，避免历史连续种子重叠问题。
6. **部署门槛**：同一批新牌山上比较净得点、一位率、平均顺位、末位率和放铳；检查弃牌、立直、红牌、吃碰后选牌及自摸没有退化。少量对局只是冒烟，不代表真人胜率。新权重应独立保存，验证通过后才启用。

历史第二轮监督训练已经出现过明显实战退化，见 `reports/2026-10-29-round2-strength/README.md`，不要直接重跑旧 `semantic-round2.toml` 并覆盖当前模型。
