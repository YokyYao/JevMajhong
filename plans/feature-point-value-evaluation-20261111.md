# 得分预测器的原生服务与完整东风对照

**进度：** [768场完整开发已完成并审计](../reports/2026-11-11-feature-point-value-development/README.md)，候选减保留组合−408.07点／场，95%区间[−2178.97，1362.82]；没有支持采用的证据，条件确认正常跳过。[采样及拟合](../reports/2026-11-11-feature-point-fit/README.md)中的MSE小幅改善没有转化为本轮净得点改善，保留原组合。

承接[96个新TRAIN牌山的得点标签方案](feature-point-training-20261111.md)。这里只把拟合出的动作差值接回冻结第二阶段的公开表征，不更新LoRA，也不声称全参数重训。当前组合的旧B普通决策和强对手保持一致。

训练标签是单次替代动作相对冻结教师的终局净得点差。服务端同样先确定第二阶段教师动作，再按原拟合器的float32规则计算每个动作的特征差，转float64乘系数；教师相对价值精确为0，完全中性的平局保留教师。不增加吃碰、跳过、番数或排名固定奖励，不设置正收益幅度门槛。返回数字是动作偏好，不是校准的胜率。

CPU机制检查覆盖原生指针概率重放、拟合与服务特征差精确对齐、普通请求原样分流、损坏教师分布拒绝，以及两种动作顺序下零增益保留教师。GPU评估加载后先用20个不同TRAIN请求核对教师概率、CPU/原生动作价值与选择，并核对6条普通请求完全不变；只使用已打开TRAIN，不触碰封存真人test。

完整对局只跑两个比较臂：冻结第二阶段鸣牌组合与新动作得分预测器，两者普通决策都由旧B负责。旧B单独一臂对本次相对父模型增益并非必要，省去额外384场。此处使用原先预留的新牌山作学习后验证，和复用历史记录的单模型诊断目的不同。

开发为10220000–10220031，四个座位、三组固定对手、两种策略共768场。逐场对齐同牌山、座位和对手；账本之和须等于终分减25000；整牌山聚合后计算32个独立单位的配对区间。记录一位/前二/四位率、和牌、放铳、吃碰及得点组成，主指标仍是候选减第二阶段的完整东风净得点。

采集和拟合完整成功后才能进入评估；整牌山CV不胜零预测则正常跳过，不把小训练损失或动作召回当作强度。开发完整审计后，均值为正才在10230000–10230127的128个独立牌山做3072场两臂确认；区间跨零时保留正向信号，但不宣称稳定。没有固定+250/+500分门槛。

单次干预数据只估计后续沿教师行动的价值。服务端连续多次改动作可能改变局面分布，因此即便CV有改善，也必须打完整新牌山，不能用CV推导胜率提升。任一完整得点比较未显示增益，保留原版并调整下一步。

两臂对照的监控可使用[只读进度快照](../scripts/snapshot_score_progress.py)的`--kind paired`模式，只计算已完成场数和完整配对牌山覆盖；全部32个登记牌山完整后才输出数值比较，不根据早期子集选模。快照不修改正式评估，也不代替Slurm存活检查及最终来源审计。
